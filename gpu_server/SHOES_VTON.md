# 상의·하의·신발 가상 피팅 확장

작성: 2026-09-19. **구현·코드 검증에 더해 실제 GPU 생성 77건(점검 5건 + 사진 6장 × 신발 4개를 프롬프트 3종으로 24건씩)까지 확인했다. 운영 기본값은 여전히 비활성이다.**

## 기존 코드에서 달라진 점

GitHub `origin/main`의 `39369de`까지 확인했다.

- PR #24: 신발 인식 헤드, 신발 추천·검색, 퍼스널 톤, 성별 입력, LLM 추천 관련 변경이 추가됐다.
- PR #25: 상품별 추천 이유와 근거 표시가 추가됐다.
- 추천에는 신발이 들어왔지만 생성은 상의·하의 두 종류만 처리했다. 화면에서도 신발 입어보기가 막혀 있었다.
- 이전 VTON 품질 개선 PR #23은 아직 병합되지 않았다. 이번 작업 브랜치는 최신 main과 해당 개선을 합쳐 기존 마스크·기장·품질 검사를 유지한다. 원래 작업 폴더의 수정사항과 가중치는 그대로 두었다.

## 생성 방식

1. 무신사에서 선택한 상의·하의의 실제 상품 이미지로 기존 CatVTON 합성을 실행한다.
2. 합성된 사진을 다시 파싱해 발과 신발의 위치를 찾는다.
3. 사진 하단 크롭, 발 마스크, 선택한 신발의 **실제 이미지**를 FLUX.2-klein-4B의 참조 이미지 인페인팅에 넣는다.
4. 생성 결과 중 발 마스크 안쪽만 원본에 합친다. 옷·얼굴·배경의 마스크 밖 픽셀은 이 단계에서 보존한다. JPEG 저장 시 압축 차이는 생길 수 있다.

상의만, 하의만, 신발만 또는 세 종류의 조합을 선택할 수 있다. 신발 단독 선택은 CatVTON을 실행하지 않는다. 상의·하의 단독 요청은 기존 어댑터로 그대로 전달한다.

양쪽 발목·발끝의 위치와 가시성을 먼저 검사한다. 발이 사진 밖에 있거나 가려졌으면 신발 합성을 막는다. 바지·치마 영역은 신발 마스크에서 제외한다. 신발 단계가 실패하면 중간의 옷 합성본을 완성본 캐시에 저장하지 않는다.

웹의 상품 선택, 서버 요청 한도, 카테고리별 조합 생성, 결과 캐시에 신발을 연결했다. 신발 모델이 준비되지 않았으면 상의·하의만 활성화된다.

## 프롬프트 A/B 24쌍 × 3종

결함 두 가지를 프롬프트로 줄일 수 있는지 **같은 사람·같은 신발·같은 시드**로 24쌍씩 세 번 생성해 비교했다.

| | v1(원래) | v2(청결 + 양말 금지) | v3(청결만, 채택) |
| --- | --- | --- | --- |
| 때 탄 질감(육안) | 20/24 | 0/24 | 3/24 |
| 없던 발목 착용물(육안) | 14/24 | 17/24 | 14/24 |
| 얼룩 대리 지표 평균 | 0.272 | 0.245 | 0.236 |
| v1보다 깨끗한 흰 신발 사례 | – | 10/12 | 10/12 |

- v2는 밑창을 가장 깨끗하게 만들었지만 **맨발목인 사람에게 없던 양말을 새로 그려 넣었다**(`MEN-Shirts_Polos-id_00000925` 3건). 프롬프트에서 "socks"를 유지 목록과 금지 문구에 세 번 언급한 것이 역효과로 보인다.
- v3은 v2에서 양말 관련 문장을 모두 빼고 청결 문장만 남긴 것이다. 때 탄 질감은 거의 사라지고 발목 착용물은 v1 수준으로 되돌아왔다. **v3을 `shoe_tryon.PROMPT`로 채택했다.**
- 세 실행 모두 24/24 성공, 오류 0건, 마스크 밖 픽셀 보존 24/24다. 생성 시간 중앙값은 11.0 / 9.3 / 8.9초, 변경 비율은 0.48~0.73 / 0.46~0.73 / 0.44~0.73으로 프롬프트에 따른 차이는 없었다.
- 대리 지표는 마스크 안에서 채도가 낮고 밝기가 중간인 화소 비율이다. 그림자·바닥도 함께 걸리므로 절댓값이 아니라 같은 사례끼리의 방향만 본다. 육안 판정을 대신하지 않는다.

### 기각한 가설: 마스크가 맨발목까지 덮어서 양말이 생긴다

마스크 경계를 결과 위에 겹쳐 확인한 결과 **사실이 아니었다**. 편집 영역의 위쪽 끝은 파싱이 찾은 발 영역보다 13px 위일 뿐이고, 마스크 안에서 다리 살 라벨은 전체의 4~5%다. 양말은 모델이 신발을 조금 낮게 그린 뒤 원래 신발 목선 자리를 채우면서 생긴다. 즉 마스크 크기가 아니라 생성 쪽 선택이다. 다리 쪽 팽창 축소·발목 위 컷 같은 마스크 변형은 GPU 없이 파싱 라벨 덤프(`--dump-parse`)로 미리 비교했고, 이 결함을 줄이지 못한다고 판단해 넣지 않았다.

## 남은 품질 확인

긴 부츠처럼 종아리까지 덮는 상품, 앉은 자세·측면 사진, 발이 서로 겹치는 사진은 아직 확인하지 않았다. 색이 바뀌었다는 사실만으로 상품 재현 성공을 판정하지 않는다.

현재 자동 검사는 마스크 보존과 무변화 결과 탐지까지다. 보고서의 `reference_fidelity=not_calibrated`는 상품 충실도 검사가 보정되지 않았다는 뜻이다. 기존 의류 품질 검사 정확도를 신발에 적용하지 않는다. 긴 부츠처럼 종아리까지 바꿔야 하는 상품과 복잡한 자세는 이 국소 마스크 방식의 추가 검증 대상이다.

운영 환경변수는 아직 켜지 않았다. 운영에 넣으려면 체크포인트를 평가 폴더 밖의 공용 경로로 옮기고, 실사용자 사진 표본으로 한 번 더 확인하는 것이 좋다. 운영 서비스와 팀원의 서버 전용 사이즈 추천 파일은 변경하지 않았다.

## 재현과 활성화

관련 구현: `ai_fashion_recommender/src/shoe_tryon.py`, `web/pipeline.py`, `web/app.py`, `web/static/app.js`.

모델 다운로드:

```bash
python gpu_server/scripts/prefetch_shoe_model.py --destination /path/to/flux-klein-4b
```

품질 확인 후 선택적으로 지정할 환경변수:

```bash
FASHION_SHOE_MODEL_PATH=/path/to/flux-klein-4b
```

환경변수를 비우면 기존 상의·하의 전용 생성으로 돌아간다. 신발 모델의 구성 파일과 가중치 샤드가 모두 있어야 신발 선택이 활성화된다.

서버 평가 위치: `/data1/dsl01/eval/shoes_vton_20260919/` (계산 노드는 `/mnt/data1/...`). 운영 릴리스와 분리되어 있다.

```bash
# GPU가 비어 있을 때: 점검 5건
sbatch gpu_server/jobs/shoes_vton_smoke.sbatch

# 확대 검증 24건. SHOES_BROAD_PROMPT 를 주면 프롬프트 A/B가 된다

# GPU가 모두 차 있고 운영 작업이 유휴일 때(서비스는 계속 실행)
srun --jobid=<fitta-web JobID> --overlap --ntasks=1 --cpus-per-task=3 --mem=20G   bash /mnt/data1/dsl01/eval/shoes_vton_20260919/run_smoke_overlap.sh
```

마스크 규칙만 바꿔 보고 싶으면 GPU를 쓰지 말고 파싱 라벨을 먼저 덤프한다. `smoke_shoe_tryon.py --prepare-only --dump-parse`는 사람별 파싱 라벨과 포즈를 저장하므로, 마스크 변형은 로컬에서 면적·겹침으로 비교할 수 있다.

입력과 마스크는 `prepared/`, 추론 결과와 보고서는 `out/`에 저장된다. 추론 실패도 `out/results.json`에 기록한다. 재실행은 `gpu_server/jobs/shoes_vton_smoke.sbatch`를 사용한다. 원본 사진과 상품 이미지는 평가 폴더에서만 보관한다.

## 2026-09-19 배포 인계 점검

- PR #26의 신발 합성과 이전 품질 개선을 main에 반영하는 작업을 이어 진행했다.
- 운영 서버에만 있던 실측 사이즈 비교·후보 검색과 최신 신발·퍼스널 톤·추천 이유 변경의 충돌을 해결했다. 배포 통합본은 별도 브랜치 `codex/shoes-release`에서 관리한다.
- 공개 게이트웨이의 기존 화면에는 성별 필드가 없어 새 API의 필수 검증과 충돌했다. `change_scope`만 보내는 구버전 요청은 기존처럼 처리하고, `change_categories`를 보내는 새 요청과 명시적으로 잘못된 성별은 기존 필수 검증을 유지한다. 사진에서 성별을 추정하거나 기본값을 임의로 넣지 않는다.
- `/api/health`에 `tryon_categories`를 추가해 모델 파일 준비에 따른 실제 지원 범위를 확인한다.
- `gpu_server/scripts/smoke_shoe_api.py`로 실제 HTTP 분석·추천·신발 배치 합성·이미지 다운로드·캐시까지 검증한다.
- 프롬프트 비교 수치는 같은 개발 사진으로 선택한 결과이며, 독립된 사용자 사진에 대한 일반화 성능 추정이 아니다.
