## 2. 중간발표 이후 달라진 것

### 2.1 사진을 받기 전에 걸러낸다 (신규)

중간발표 때는 아무 사진이나 받아 분석했다. 지금은 두 겹의 관문이 있다.

- **`POST /api/validate-photo`** — 조건 입력 **전에** 사진만 검사하고 검사 파일은 즉시 삭제한다.
  부적합하면 구체적 사유와 함께 재선택을 안내한다.
- **몸선 가림 판정** (`src/body_visibility.py`, PR #48) — 치마·두꺼운 외투·넉넉한 옷이 몸선을 가리면
  체형 규칙만 보류하고 서비스 진행은 막지 않는다.

**이 관문은 한 번 크게 틀렸다가 고쳤다.** 처음엔 가림이 의심되면 진행을 막았는데, 정상 사진의 93%가
차단됐다. 재봉의 **여유량(ease)** — 착용 여유와 디자인 여유의 구분 — 을 정의 근거로 삼고
Fashionpedia(ICCV 2020)의 실루엣 속성(tight/regular/loose/oversized/baggy/wide-leg)을 정답으로
재보정해 **오차단 16%** 로 내렸다. 지금은 `passed = status != "occluded"` 로, 애매하면 경고만 남긴다.

```
확인: src/body_visibility.py 의 policy_version "2026-09-23b", docstring 의 신호 표
      reports/body_visibility_2026-09-23.md
```

### 2.2 체형 분류에 근거를 붙였다

중간발표 때는 어깨/골반 비율의 경계값이 임의값이었다. 지금은 **기준 분포의 백분위**다.

- 측정량: `shoulder_hip_ratio` = MediaPipe `pose_world_landmarks`(3D 미터)의 어깨 관절 간격 ÷ 골반 관절 간격
- 표본 n=721 (Fashionpedia + Fashion200k 5,363장을 전신·정면·`full_body_score ≥ 0.85` 로 필터)
- 경계: **33 백분위 1.4068 / 67 백분위 1.4573** → 삼각 / 사각 / 역삼각
- 분류 출처: Size Korea 『한국인의 표준체형』, 상반신 분류는 Rasband(1994) 8분류

**정직하게 적어 둔 한계:** 이 표본은 서양 패션모델 상품컷이고 한국인 표본이 아니다.
Size Korea 의 어깨사이길이·엉덩이너비는 **신체 표면 치수**라 관절 간격과 재는 대상이 달라 그대로 못 쓴다.
모래시계·마름모꼴·둥근 체형은 가슴·허리·엉덩이 **둘레**가 필요해 사진만으로는 판정하지 않는다
(사용자가 둘레를 직접 입력하면 `src/body_shape.py` 가 판정한다).


### 2.3 상품 데이터를 실측·색·카테고리로 채웠다 (가장 많이 바뀐 부분)

중간발표 때는 상품명과 이미지만 봤다. 지금은 무신사 상세 API 세 개를 더 쓴다.

| 가져온 것 | 쓰는 곳 |
|---|---|
| 실측표 (`/actual-size`) | 사이즈 비교, 카테고리 검증 |
| 색 옵션 (`/options` 의 COLOR_CHIP) | 색 조건 비교 |
| 실측표 `typeName` | 무신사 카테고리 오류의 안전망 |

**(a) 색 — 어디서 읽을지 측정해서 정했다.**

| 출처 | 대표 사진과의 일치율 |
|---|--:|
| 상품명 (상의) | 78% |
| 상품명 (하의) | 75% |
| 첫 번째 컬러칩 | 46% |
| 사진 추정기 (RGB 최근접) | 43% |

→ **상품명을 1순위로** 올렸다. 합성에 쓰는 옷은 대표 사진의 옷이므로, 추천한 색과 합성되는 색이
달라지면 추천 자체가 무의미해진다는 판단이다.

상품명에서 색을 읽을 때 **규격화된 어휘표**를 뒀다(`data/catalog_derivation.json` 의 `color_vocabulary`).
그냥 부분 문자열로 찾으면 **'블루종'이 블루로 42건**, 영어 어미(LAYERED·TEXTURED·Tailored)의
**RED 가 21건** 잡힌다. 비색 용어를 먼저 지우고, 영어는 왼쪽 경계를 보고, 한 글자 색은 버리고,
가장 긴 단어가 이긴다.

색이 없는 상품은 **우리 의류 영역 분할 모델로 옷 영역을 추출해 거기서 색을 판정**한다.
RGB 최근접은 어두운 옷을 전부 검정으로 보내므로, 명도·채도를 먼저 가르고 색상환으로 고른다
(58% → **69%**, 확신도 0.8 이상만 보면 **87%**). 381개 중 152개를 채웠고 **229개(10.3%)가 남았다.**
사진에서 정한 색은 **빈 칸만 채우고 회피 색 필터에는 쓰지 않는다** — 오차가 어두운 색을 블랙으로
뭉개는 쪽이라 멀쩡한 상품이 통째로 사라지기 때문이다.

근거 없이 쌓여 있던 **'그레이' 329개를 지웠다**(옛 크롤러가 색을 못 찾으면 기본값으로 넣고 있었다).

**(b) 카테고리 — 무신사가 틀릴 때의 안전망 (PR #57)**

무신사에서 하의가 상의로 분류된 상품이 있다. 그런데 그 상품의 **실측표는 하의 항목(허리단면·총장)**
으로 나온다. 그래서 실측표 `typeName` 으로 부위를 교차 검증해 어긋나면 후보에서 뺀다.
`오버올`처럼 양쪽으로 팔리는 종류는 판정을 보류한다.

> 정직하게: **재현은 못 했다.** 실시간 검색 659개, 카탈로그 2224개에서 오분류가 0건이었다.
> 사용자가 본 사례를 재현하지 못한 채로 안전망만 넣었다.

**(c) 사이즈 비교 — 신체 치수를 추정하지 않는다**

사용자가 **잘 맞는 옷의 실측**(상의 가슴단면·총장 / 하의 허리단면·총장)을 입력하면, 상품 사이즈표의
같은 항목과 비교한다. 사진·키·체중으로 단면을 추정하지 않는다.

```python
# src/size_fit.py (배포본 a9efcde)
weights  = [2 if 단면 else 1]                      # 착용감에 결정적인 단면에 2배
distance = Σ(|delta| × w) / Σ(w)                    # 두 항목이면 (2×|단면차| + |총장차|) / 3
ranking_bonus = max(0.0, 1.0 - distance / 10.0)     # 0~1, 클수록 먼저
```

**중요한 성격:** `ranking_bonus` 는 **점수가 아니라 정렬 보조값**이고, **값이 클수록** 위로 온다
(`_sort_key` 가 `-(retrieval_score + bonus)` 로 정렬). 그리고 **두 항목을 모두 갖춘 경우에만** 부여한다
— 부분 측정과 미측정은 0점이다. 누락을 부적합으로 오인하지 않기 위한 설계다.
코드 주석도 그렇게 적어 두었다: `실측 유사도의 작은 보조점수일 뿐 착용 성공 확률은 아니다.`

### 2.4 합성 품질을 자동으로 판정한다

중간발표 때는 합성 결과를 눈으로만 봤다. 지금은 `src/tryon_quality.py:assess_tryon` 이 검사하고,
**되살릴 수 있는 실패일 때만 1장 더 생성**한다(구조적 실패는 재생성해도 같으므로 낭비하지 않는다).

검사 항목: 마스크 밖 픽셀 보존(PSNR), 얼굴 보존, 의류 덮음 비율, 몸통 피부 노출(마스크 안/밖 구분),
상품 반영도, 색 차이(ΔE), 선명도, 기장 차이.

**레퍼런스 거절** — 상품 사진이 몸통 크롭이거나 옷이 너무 작게 담혔으면 합성 전에 거절한다.
다만 `coverage < 0.25` 는 **거절이 아니라 경고**다. 2026-09-21 A/B 에서 같은 36쌍의 해상도를
4~9배 올려 coverage 미달을 33건→0건으로 만들었는데 **상품 유사도는 0.775→0.778 로 그대로**였다.
"다른 옷이 그려진다"는 애초 가정이 반박된 것이라, 문구에서 그 주장을 뺐다.
