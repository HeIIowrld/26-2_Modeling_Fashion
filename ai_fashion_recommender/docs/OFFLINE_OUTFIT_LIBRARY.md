# 코디 조합 사전 계산

상의, 하의, 신발 조합의 점수를 먼저 저장한다. 사용자가 유지할 옷과 변경할
카테고리를 지정하면 저장된 조합을 조회하고, 선택한 상품만 사용자 사진에 합성한다.
검색 과정에서 모든 후보를 다시 합성하지 않는다.

## 계산 범위

- 무신사 인기순 첫 페이지에서 상의, 하의, 신발 각각 최대 100개를 수집한다.
  품절, 잘못된 메타데이터, 이미지 다운로드 실패 상품은 제외하고 실패 원인을 기록한다.
- 전체 인기 상의에 흰 반팔이 없을 수 있어 반팔 카테고리에서 별도의 실제 상품
  레퍼런스를 추가한다. `reference_anchor`로 구분하며 인기 100위 안이라고 표시하지 않는다.
- `--all-contexts`: 6개 상황 × 6개 스타일 × 3개 체형 × 2개 하체 비율 = 216개 조건.
  체형과 비율 조건은 규칙 계산용 가정이다. 실제 사람 216명을 측정했다는 의미가 아니다.
- 100 × 100 × 100이면 상품 조합은 100만 개, 조건별 점수는 2억 1,600만 개다.
  레퍼런스 상품을 추가하면 그만큼 늘어난다.
- 초기 렌더링 계획은 흰 반팔을 유지하고 하의와 신발을 바꾸는 사례다.
  모든 조건에서 상위 3개를 뽑고 동일한 상품 조합과 대표 체형 조건은 중복 제거한다.
  전체 삼중 조합을 실제로 렌더링했다거나 전역 최적 조합을 찾았다는 의미가 아니다.

## 점수와 벡터

예상 점수는 기존 상·하의 진단 점수 85%와 신발 관계 점수 15%를 합산한다.
신발 관계는 상품명에서 확인한 종류, 의류와의 격식 차이, 색상 관계의 평균이다.
없는 속성은 중립 점수로 처리한다. 이 가중치는 실험용이며 사용자 평가로 검증되지 않았다.

상품 속성 헤드의 판정, 상품명에서 확인한 정보, 유도한 속성의 출처를 저장한다.
상품명에서 확인하지 못한 색은 회색 같은 임의의 값으로 채우지 않는다.
소재나 핏 등 모델이 판정한 속성에는 오류가 있을 수 있다.

벡터는 두 종류다.

1. 상품 이미지와 실제 합성 이미지의 FashionSigLIP 임베딩: 시각적 검색용이다.
   임베딩 유사도 자체를 코디 적합도 점수로 해석하지 않는다.
2. 조합의 10차원 점수 벡터: 상의와 하의의 체형·상황·스타일 점수,
   상·하의 조화, 신발의 스타일·격식·색상 관계다.

실제 합성 후에는 옷을 다시 분석해 점수를 별도로 저장한다. 신발 인식 모델은
아직 학습되지 않았으므로 신발 부분은 상품 속성을 계속 사용한다. 렌더링한 신발의
정확한 형태나 상품 일치도를 시각적으로 채점한 값이 아니다.

합성 완료와 추천에 사용할 수 있는 상태를 구분한다. 기존 품질 검사 외에 상품과
결과의 하의 종류, 조거·하렘 등 종류 충돌, 바지통·밑단 비율, 상의 종류와 겹침을
검사한다. 바지통은 다리 사이 빈 공간을 제외한 옷 픽셀 수로 측정하며 잘린 밑단과
작은 오분할 조각은 제외한다. 상품 사진 대비 비율 허용 범위 0.75~1.35는 잠정값이다.
실제 치수나 핏 정확도를 측정한 값으로 해석하지 않는다.

자동 검사를 통과해도 `auto_passed`이며 검수 대기 상태다. 실제 상품·원본·결과를
비교한 검수 기록이 있어야 `complete`가 된다. 미측정은 `unassessed`, 자동 실패는
`quality_failed`, 시각 검수 거절은 `visual_rejected`로 남긴다. 기존 버전의
`complete` 기록은 새 검사를 통과한 것으로 취급하지 않는다.

## 실행

저장소 루트에서 실행한다. 이미지, 모델 벡터, 점수 배열과 인물 파생 이미지는
Git에서 제외되는 `data/cache/` 또는 서버의 별도 평가 디렉터리에 저장한다.

```bash
PYTHON=.venv-web/bin/python
SCRIPT=ai_fashion_recommender/scripts/precompute_outfits.py
RUN=ai_fashion_recommender/data/cache/outfit_library

# 1. 실행 디렉터리별로 수집 시각과 원본 응답을 고정한다.
"$PYTHON" "$SCRIPT" fetch --root "$RUN"

# 2. 모델이 있는 환경에서 상품 속성과 이미지 벡터를 만든다.
"$PYTHON" "$SCRIPT" prepare --root "$RUN" --device auto

# 3. 모든 스타일·상황의 조합 점수를 저장한다.
"$PYTHON" "$SCRIPT" index --root "$RUN" --all-contexts
"$PYTHON" "$SCRIPT" plan --root "$RUN" --per-scenario 3

# 4. 실제 사진과 상품의 분할·착장 분석을 캐시한다.
"$PYTHON" ai_fashion_recommender/scripts/inspect_offline_outfits.py \
  --root "$RUN" --output "$RUN/evidence" --people /path/to/reference_people

# 5. 별도 GPU에서 상위 조합을 합성하고 상품 보존 여부를 검사한다.
"$PYTHON" "$SCRIPT" render --root "$RUN" \
  --people /path/to/reference_people --shoe-model /path/to/flux-klein-4b \
  --evidence "$RUN/evidence" --max-renders 12

# 6. 원본·상품·결과를 실제로 확인한 다음에만 검수 결과를 기록한다.
"$PYTHON" "$SCRIPT" review --root "$RUN" \
  --record "$RUN/renders/<combination>/<render>.json" \
  --decision accepted --reviewer '<검수자>' --notes '<확인한 항목과 결과>'

# 7. 이후 조회에는 생성 모델이나 이미지 인식 모델이 필요 없다.
"$PYTHON" "$SCRIPT" query --root "$RUN" \
  --scenario '데일리/캐주얼/역삼각체형/short' --gender 남성 \
  --kept '{"top":{"color":"화이트","item_type":"티셔츠","sleeve_length":"반팔"}}' \
  --verified-only
```

`--verified-only`는 같은 체형·하체 비율 구간에서 합성·재분석·상품 보존 검사·시각 검수가 끝난 후보만
합성 후 점수순으로 반환한다. 검증된 후보가 없으면 빈 목록을 반환한다.
이 옵션이 없으면 전체 인덱스의 예상 점수순으로 반환한다.
예산은 새로 구매할 상품에만 적용한다. 유지하는 옷은 품절이어도 조건으로 사용할 수 있다.
예산을 제한하려면 `--max-budget 150000`을 추가한다. 최초 합성 계획은 예산 제한 없는
상위 점수 기준이므로, 예산을 적용하면 검증된 후보가 없을 수도 있다.
상의와 하의를 모두 고정하고 신발만 바꾸거나, 하의와 신발을 고정하는 조회도 가능하다.
현재 조회는 정확히 일치하는 속성 또는 상품 ID를 사용한다. 사용자 사진 임베딩으로
가장 가까운 대표 상의를 찾아주는 웹 연결은 아직 구현하지 않았다.

대표 사진은 두 발이 보이고 체형·비율 구간과 성별 조건이 맞아야 한다. 같은 구간의
전체 후보 중 단일 상의, 하의 종류·기장·실루엣이 상품과 맞는 사진을 우선한다.
치마·원피스의 잔여 영역, 아우터, 보이지 않는 발, 불확실한 포즈는 제외한다.
현재 보존 검사와 대표 사진 선택은 긴바지 조합을 지원하며 다른 하의 형태는 보류한다.
해당 사진이 없으면 `missing_reference`로 기록한다. 다른 체형의 합성 결과로
검증 완료를 대신하지 않는다. 같은 구간에 속해도 사용자 개인의 착용 결과는 달라질 수 있다.

## 산출물과 재개

- `popular_*.json`: 수집 URL, 시각, 원본 상품 목록.
- `catalog.json`, `products/`, `images/`: 상품 속성, 출처, 모델 체크섬, 개별 임베딩과 사진.
- `index.json`, `scores-*.npy`, `scores-*.npz`: 조건 목록과 점수. 큰 배열은 메모리 매핑으로 읽는다.
- `render_plan.json`, `references.json`: 실제 합성 대상과 사용 가능한 대표 사진.
- `evidence/`: 입력 이미지·분석 코드·속성 모델 체크섬을 포함한 분할 맵과 착장 분석.
- `render_manifests/`: 합성 코드, 모델 버전·파일 정보, 설정을 기록한 실행 명세.
- `renders/`: 조합·대표 체형별 합성 이미지, 임베딩, 재분석 점수, 오류와 품질 기록.

준비 단계는 완료된 상품 캐시를 재사용한다. 렌더링 캐시 키에는 실제 대표 사진,
세 상품 이미지, 합성 코드·모델·설정을 포함하므로 입력이 바뀌면 이전 이미지를
재사용하지 않는다. 검수는 결과 이미지의 SHA-256에 연결되며 이미지가 바뀌면 무효다.
점수 계산과 검수 코드를 분리해 검수·조회 변경 때문에 전체 점수를 다시 계산하지 않는다.
이전 통합 파일 지문으로 만든 인덱스는 한 번 재생성해야 한다.
`--max-renders 0`은 남은 계획 전체를 수행한다. 같은 출력 디렉터리에 두 작업을
동시에 실행하지 않는다. Slurm 실행 파일은 파일 잠금으로 중복 실행을 막는다.
`status --root "$RUN"`으로 전체 계획과 완료·실패·대기 건수를 확인할 수 있다.
모델이나 상품 원본 응답이 바뀌면 상품 캐시 키가 바뀌며,
점수 코드·규칙이 바뀐 인덱스는 조회를 거부하므로 다시 생성해야 한다.
인기 목록을 새로 수집할 때는 새 실행 디렉터리를 사용한다.

서버에서는 `gpu_server/jobs/outfit_library.sbatch`를 사용한다.
`FITTA_LIBRARY_PROJECT`는 격리된 코드 경로, `FITTA_LIBRARY_OUTPUT`은 해당 실행의
출력 경로다. `FITTA_LIBRARY_STAGE=prepare`는 벡터와 점수 계산만,
`FITTA_LIBRARY_STAGE=render`는 합성만 실행한다. `inspect`는 사진 분석을 캐시한다.
`compare`는 보고서에 고정한 두 하의 상품으로 기존·새 하의 합성 방식을 비교한다.
시간 제한 이후 같은 디렉터리로
렌더링을 재제출할 수 있다. 운영 웹 서비스와 별도 작업으로 실행한다.

이 배치는 사전 계산과 조회 검증용이다. 운영 웹의 실시간 검색 경로를 교체하거나
사용자 사진을 영구 라이브러리에 저장하지 않는다.

## 합성 방식 비교

`--lower-backend flux`는 보유한 FLUX 모델로 하의를 상품 참조 이미지에 맞춰 편집하는
실험 옵션이다. 상의는 기존 CatVTON, 신발은 기존 신발 편집기를 쓴다. 하의 편집은
상의 합성 후 다시 파싱한 영역을 기준으로 하며 상의·손·발은 보호한다.
기본값은 `catvton`이다. 실험 옵션을 전체 상품에 검증된 방식으로 해석하지 않는다.

`--reference-name`과 `--combination-ids`로 같은 사진·상품을 고정해 비교할 수 있다.
명시적으로 지정한 사진은 대표 사진의 적합성 필터를 우회하므로 평가에만 사용한다.
체형·비율·성별 조건과 합성 후 검사는 그대로 적용한다.

기존 결과를 재합성하지 않고 새 기준으로 감사하려면 `inspect_offline_outfits.py`로
그 결과의 분할 맵을 저장한 뒤 다음 명령을 실행한다. 원본 기록은 바꾸지 않는다.

```bash
"$PYTHON" "$SCRIPT" audit --root "$RUN" --evidence "$RUN/evidence"
```
