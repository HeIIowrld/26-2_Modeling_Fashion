# Fashion Rules 기반 상품 사진 재정렬

## 목표

상품명에 `와이드`, `오버핏` 같은 단어가 있어야만 핏 규칙을 적용하던 한계를 줄인다.
새 핏 라벨을 만들거나 모델을 재학습하지 않고, 현재 배포된
`upper_fit`·`lower_fit`·`pant_leg_shape` 헤드를 상품 후보에 재사용한다.

## 실행 순서

1. 성별·카테고리·소재·색상·스타일 조건으로 무신사 후보를 수집한다.
2. 핏 단어가 들어간 검색어도 장애 시 대체 경로로 유지하지만, 기본 검색어에는 핏을 강제하지 않는다.
3. 카테고리별 최대 300개 후보를 보관한다.
4. 상품명에 요청 핏·기장 단서가 없는 후보 중 상품 종류·핏 단서·브랜드가
   서로 겹치지 않도록 최대 8개를 비전 sample로 선택한다.
5. 상품 사진이 실제 착용 사진인지 FASHN 분할로 확인한다.
6. 기존 속성 헤드로 핏과 기장을 추정한다.
7. 0.90 이상 단일 판정만 사용한다. 하의의 `lower_fit`과 `pant_leg_shape`가 모두
   높은 신뢰도인데 서로 다르면 보류한다.
8. 현재 요청에서 실제 활성화된 Fashion Rule이 만든 핏·기장만 순위에 반영한다.
9. 규칙과 일치하는 판정은 상품명 일치와 같은 크기의 점수를 받고, 확실한 불일치는 감점한다.
10. 상황 적합도와 비전 판정을 먼저 반영해 후보를 재정렬한 뒤 조합기로 넘긴다.
11. 조합기는 비전에서 관찰한 실제 핏으로 `R-SIL-01`과 `R-CMP-03`의 상·하의
    실루엣 조화를 계산한다.
12. 마지막 단계에서 다양성 제약을 적용한다. 카테고리별 후보가 3개 이상이면
    최종 코디 3개가 같은 상의·하의·신발을 반복 사용하지 않게 선택한다.

## 실행 시간과 진단 정보

- 상품 사진 분석 제한시간은 요청당 최대 1.0초다.
- 응답의 `engine.product_search.photo_attributes`에 사진 분석 후보 수,
  실제 분석 성공 수, 커버리지와 표본 그룹을 기록한다.
- 사진 판정 커버리지는 `title_only`, `limited_photo_assist`,
  `photo_assisted`로 구분한다. 따라서 상품명만으로 정렬됐는지, 일부 또는
  충분한 사진 근거가 순위에 반영됐는지 확인할 수 있다.

## 기존 라벨 사용

- 상의: 슬림핏, 레귤러핏, 여유핏, 오버핏
- 하의: 슬림핏, 스트레이트핏, 테이퍼드핏, 와이드핏, 플레어핏
- 바지 실루엣 보조 헤드: 스키니, 스트레이트, 테이퍼드, 페그, 부츠컷,
  플레어, 와이드, 팔라초

바지 실루엣 보조 헤드는 기존 하의 핏 라벨로 정규화한다. 예를 들어
`스트레이트`는 `스트레이트핏`, `와이드`와 `팔라초`는 `와이드핏`으로 사용한다.
`세미와이드`처럼 현재 학습 라벨에 없는 클래스를 임의로 새로 만들거나
`와이드핏`으로 단정하지 않는다.

## 안전 조건과 한계

- 평면 누끼 상품 사진은 현재 정책에서 핏 근거로 사용하지 않는다.
- 모델 신뢰도가 낮거나 두 하의 헤드가 충돌하면 상품명 기반 결과로 돌아간다.
- 비전 판정 실패가 사진 분석 전체나 무신사 검색을 실패시키지 않는다.
- 제한시간 안에 분석된 표본이 적으면 사진 근거를 과장하지 않고
  `limited_photo_assist` 또는 `title_only`로 표시한다.
- 상품 사진 판정은 검색과 코디 조합에 사용되며, 가상착장 마스크 문제는 이번 변경 범위가 아니다.
- sample 크기와 0.90 임계치는 실제 사람 라벨 평가 후 별도로 튜닝해야 한다.

## 검증 지표

- 비전 sample 중 실제 판정률과 보류율
- 핏별 precision·recall·macro-F1
- 상품명에 핏 단어가 없는 후보의 Precision@3
- 비전 적용 전후 최종 조합의 Fashion Rules 점수
- 콜드 요청과 캐시 요청의 P50/P95 지연 시간
