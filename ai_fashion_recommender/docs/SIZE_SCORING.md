# 사이즈 점수와 운영 개선

## 평가하는 것

사진·키·체중·신체 둘레를 의류 단면으로 변환하지 않는다. 사용자가 입력한 잘 맞는 옷의 실측과 상품 사이즈표의 같은 항목을 비교한다. 상의는 가슴단면·총장, 하의는 허리단면·총장이 모두 있어야 점수를 낸다. 단면을 둘레로 오인하거나 cm 외 단위를 임의 변환하지 않는다.

두 항목의 차이 중 더 불리한 항목을 점수로 삼는다. 차이 1cm까지 100점, 그 이후 단면은 추가 5cm, 총장은 추가 10cm에 걸쳐 선형으로 0점까지 내려간다. 이는 초기 순위 휴리스틱이다. 신축성, 밑위·허벅지·엉덩이 여유량, 사용자가 새로 원하는 오버핏/크롭 기장의 적합성이나 실제 착용 성공률을 검증한 기준이 아니다. 같은 용도·핏의 기준 옷을 입력할수록 비교가 유용하다. 치수 차이만으로 상품을 착용 불가로 제외하지 않는다.

## 점수 경로

- 오프라인 추천의 기존 배점식은 최종 진단 점수로 덮어써지고 있었다. 실제 최종 점수에 `0.85 × 진단 점수 + 0.15 × 실측 비교 점수`를 적용했다. 기준 옷 입력이 없으면 기존 점수를 유지한다.
- 정보가 부족한 슬롯은 중립 50점이며, `size_fit_coverage`를 별도로 기록한다. 두 벌 중 한 벌만 평가했으면 평가 범위는 50%다. 미확인과 알려진 큰 차이를 구분한다.
- 현재 착장과 교체 후보의 개선폭을 비교할 때도 같은 15% 축을 쓴다. 현재 착장 실측은 모르므로 중립 50점이다. 사이즈 입력만으로 교체 이득이 줄어드는 척도 불일치를 방지한다.
- 실시간 검색은 텍스트·사진 축의 최대 기본 배점을 환산해 사이즈 15%를 적용한다. 측정하지 않은 후보도 동일한 중립값을 쓰며 작은 보너스를 중복 가산하지 않는다. 이는 추천 품질의 확률이 아니다.
- 완전한 실측표가 있는 옵션을 우선하고, 그중 위 점수가 높은 옵션을 선택한다. 점수와 추천 사이즈가 서로 다른 기준으로 선택되지 않는다.

## 재고·결측 처리

알려진 품절 옵션은 사이즈 비교에서 제외한다. 전체 실측 사이즈가 품절이어도 실측이 없는 다른 판매 옵션이 있으면 상품 전체 품절이라고 단정하지 않는다. 여러 색을 파는 경우 비교 결과와 원하는 색상 재고는 별개임을 표시한다. 옵션 `activated=true`만으로 재고를 보장하지 않는다.

온라인 클라이언트가 만든 `data/cache/product_measurements/<상품ID>.json`을 오프라인 카탈로그도 읽는다. 캐시의 사용자 정보는 없다. 실측은 재사용하지만 1시간 이상 된 옵션 재고는 미확인으로 처리하며, 장시간 실행 중에도 재고 유효시간을 검사한다. 캐시가 없는 상품은 미확인이다. 서버를 재시작하면 새로 채운 오프라인 캐시를 읽는다.

```powershell
python ai_fashion_recommender/scripts/backfill_product_measurements.py --category bottom --limit 20
python ai_fashion_recommender/scripts/backfill_product_measurements.py --category top --limit 20
```

한 번에 20개를 기본으로 조회한다. `--offset`으로 다음 구간을 수집하고 `--report`로 상품별 진행 결과를 남길 수 있다. 일시 오류는 재시도하고, 429 재시도 한도를 넘으면 중단한다. 다른 조회 오류는 기록하고 마지막에 실패 상태를 반환한다. 옵션 조합이 많은 상품은 배치에서만 응답을 최대 8MB까지 허용하며, 실시간 조회의 2MB 제한은 유지한다.

2026-09-29 전체 2,224개 조회 완료: 실측 확보 1,853개, 실측 미제공/유효 항목 없음 371개. 단면과 총장이 함께 있어 비교 가능한 상품은 상의 1,450개·하의 379개다. 캐시는 Git 추적 대상이 아니므로 배포 서버에서는 별도 수집하거나 `outputs/catalog_backfill/catalog_enrichment_2026-09-29.zip`의 `data/`를 전달해야 한다. 세부 집계와 한계는 [전체 보강 보고서](CATALOG_ENRICHMENT_2026-09-29.md)에 기록했다.

## 함께 수정한 운영 문제

- `/api/analyze`: 단일 프로세스 기준 동시 분석/업로드 2개, 분당 6개, 보관 중 결과 20개를 넘으면 429와 Retry-After를 반환한다. TTL이 남은 기존 결과를 개수 제한 때문에 지우지 않는다. 다중 worker/서버로 확장할 때는 공유 한도 저장소가 필요하다.
- `/api/health`: 기동한 Python 릴리스 `revision`과 정적 파일 릴리스 `static_revision`을 구분한다. REVISION 파일이 없으면 null이다.
- 재고 수집 시각을 크롤러→보강 CSV→카탈로그→대체 상품 카드에 전달한다. 기존 CSV에 과거 날짜를 추측해서 넣지 않으며, 누락 시 시점 미상으로 표시한다. 오래된 재고의 실시간 검증을 대체하지 않는다.
- 색 보강에 `--missing-only`, 하의 수집에 `--category bottom --output <별도 CSV>`를 추가했다. 조회 실패가 기존 색을 지우지 않게 했다. 대표 사진과 첫 컬러칩이 다른 경우가 있으므로 색 미상 상품 전부를 칩 첫 색으로 채우지는 않았다.
- 둘레 기반 모래시계·마름모꼴·둥근체형도 균형 목표의 카탈로그 규칙을 평가한다. 특정 부위를 강조하도록 임의로 매핑하지 않는다.
- Windows JSON 읽기를 UTF-8로 통일하고 신발 의존성 오류를 TryOnNotReady로 처리한다.

## 남은 데이터·모델 작업

전체 실측 조회와 색상 미상 229개 검토를 완료했다. 실측 결측 371개와 대표 색 미상 34개는 근거 없이 채우지 않았다. 하의 후보 확충은 별도 작업으로 남아 있다. R-SIL-02의 실제 당김·여유량 판단, 색 면적/포인트 반복, 레이어드 밑단, 액세서리 색 조화도 이번 변경으로 구현됐다고 표시하지 않는다. GPU 합성 재검증과 운영 배포는 수행하지 않았다.

검증: 추천·사이즈·상품 검색·조합·세션·웹 관련 pytest 363개 통과, 71개 subtest 통과. Windows 심볼릭 링크 생성 권한 때문에 hot-swap 검사 1개는 건너뛰었다. 마지막 호환 필드/안내 문구 수정 후 관련 73개 검사도 다시 통과했다. JavaScript 구문 검사와 `git diff --check`를 통과했다.
