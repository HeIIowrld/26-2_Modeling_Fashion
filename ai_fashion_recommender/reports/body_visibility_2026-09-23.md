# 옷에 가려진 체형: 원인과 입력 검사

## 확인한 저장소 상태

2026-09-23 origin/main `0c9adee` 기준. 최근에는 신발 합성 검증(#32), 화면 무재시작 갱신(#35), GPU 작업 제한 24시간(#34), 대기 작업 재시작 방지(#36), HEIC·회전 처리(#37, #40), 정면 전신 사전 검사(#39), 부적합 상품 사진 거부(#41), 긴 바지 마스크 개선(#43), 팔 자세 오판 수정(#44), 상품 속성 평가(#42), 신발 학습 파이프라인(#45), Windows 테스트 수정(#46, #47)이 병합됐다. 이는 소스 상태이며 실제 서버 배포 상태를 확인한 것은 아니다.

`review/body-shape-weight-tuning`은 체형별 추천 점수 가중치 실험이다. 옷 안의 체형을 복원하는 변경은 아니다. 이 브랜치의 실험 결과를 이번 입력 검사 성능으로 사용하지 않았다.

## 원인

MediaPipe의 관절 추정과 체형 폭 측정은 별개다. `body_measure.py`는 사람 분할 마스크에서 가슴·허리·골반 높이의 폭을 구한다. 이 마스크에는 옷이 포함된다. `body_shape.classify()`가 그 폭을 둘레 분류 기준에 넣으므로 넓은 옷이 체형 판정을 바꿀 수 있다. 정면 폭의 비율과 둘레의 비율도 같은 값이 아니다.

기존 업로드 검사는 해상도·선명도·관절·구도를 확인하지만, 몸선이 의류에 가려졌는지는 확인하지 않았다. 가상 착용 마스크를 개선해도 이 체형 분류 문제까지 해결되지는 않는다.

## 대안 조사와 선택

사진을 거부하는 것만이 이론적인 해법은 아니다. 실제 둘레 입력, 몸선이 보이는 별도 사진, 여러 시점의 사진·스캔으로 관측 정보를 늘릴 수 있다. 현재 프로필에는 둘레 입력을 우선하는 경로도 있다. 다만 둘레를 입력해도 합성 사진에 가려진 몸의 외형을 복원해 주지는 않는다.

Models에서 `ckpt/4D-Humans`, `camenduru/4D-Humans` 등 사본이 검색됐고, Datasets에서는 `lzzcd001/Cloth3D-GShell-Datasets`가 검색됐다. 공식 배포·원본 모델 약관·체형 정답 적합성은 별도 확인이 필요하다. `shapy` 모델 및 `4DHumans`/`4D-Humans` Space 검색에서는 결과가 없었다. 검색 결과 없음은 전체 Hub에 관련 자료가 없다는 뜻이 아니다. 이 자료를 다운로드하거나 학습·추론을 실행하지 않았다.

[착의 상태 체형 복원 연구](https://files.is.tue.mpg.de/black/papers/BalanThesis2010.pdf)는 느슨한 옷의 실루엣이 내부 몸체에 느슨한 제약만 주어 추가 가정이 필요함을 설명한다. 따라서 이번 구현은 보이지 않는 몸체를 임의로 만들지 않고 입력 적합성을 검사한다.

## 구현한 정책

- 기존 FASHN 분할과 착장 속성 결과를 재사용한다. 새 모델이나 의존성은 추가하지 않는다.
- 유의한 치마·원피스 영역, 학습 속성이 지지하는 여유핏·오버핏·와이드핏·배기핏 등, 두꺼운 외투는 진행을 막고 재촬영을 안내한다.
- 마스크 폭만으로 나온 넉넉한 핏은 확정 판정 대신 `uncertain`으로 보류한다. 파서 미준비·핏 분석 불가도 통과시키지 않는다.
- 뚜렷한 가림 신호가 없으면 `no_obvious_occlusion`이다. 실제 골격·체형이 정확하다는 인증이 아니다.
- `/api/validate-photo`와 실제 `run_pipeline` 모두 같은 정책을 사용한다. 사전 검사 API를 건너뛰어도 체형 분류·상품 검색·합성 전에 중단한다.
- 별도의 체형 사진도 해당 사진의 관절과 착장을 분석하여 확인한다. 현재 보수적인 정책에서는 별도 사진·둘레 입력이 부적합한 주 사진의 통과 예외가 되지는 않는다.
- 사전 검사는 기존 분석 잠금을 공유하며 스레드 풀에서 실행하여 웹 이벤트 루프를 막지 않는다. 조건 입력 전 의류 분석 시간이 추가된다. 본 분석에서는 이미 계산한 착장 결과를 재사용한다.
- 업로드 화면에 몸선을 가리지 않는 상의와 바지를 권장한다. 오류 안내는 노출이 많은 옷이 필요하지 않다고 명시한다.

## 검증과 남은 한계

최종 전체 자동 검사: **633 passed, 5 skipped, 669 subtests passed**. 제외된 검사는 신발 학습 의존성(scikit-learn)이 없는 환경의 4개와 심볼릭 링크를 만들 수 없는 환경의 1개다. diff 공백 검사 통과.

회귀 검사는 치마·원피스, 넉넉한 상·하의, 마스크 근거만 있는 불확실성, 분할 잡음, 외투, 파서 미준비, 정상 입력, 직접 분석 경로 차단, 별도 체형 사진, 검사 후 임시 파일 삭제를 포함한다.

이 수치는 코드 동작 검사이며 사진 판별 정확도가 아니다. 실제 사진의 정상 거절률·가림 놓침률은 아직 평가하지 않았다. 파서의 치마·원피스 영역 1% 기준은 작은 잡음을 제외하기 위한 잠정 정책이고, 모든 치마·원피스를 보수적으로 제한하므로 몸에 붙는 치마도 거절될 수 있다. 넉넉한 핏 분류 자체가 틀리면 정상 사진도 보류되거나 부적합 사진이 통과할 수 있다. 체격이 큰 사람의 마스크 기반 와이드핏 오판 역시 사람의 검수로 확인해야 한다. 성별·체중·BMI 기준은 추가하지 않았다.

운영 적용 전에는 동일인·유사 자세에서 몸선을 가리지 않는 옷과 넉넉한 옷을 비교하고, 치마·외투·와이드팬츠·일반 바지 및 다양한 체격별로 검수해야 한다. 가림 판정과 통과율을 확인해야 하며 원래 체형 정답 없이 '실제 체형 복원 성공'으로 평가하면 안 된다.

이번 작업은 별도 브랜치의 구현·검증이다. main 병합과 운영 배포, 실제 GPU 추론 검증은 수행하지 않았다.
