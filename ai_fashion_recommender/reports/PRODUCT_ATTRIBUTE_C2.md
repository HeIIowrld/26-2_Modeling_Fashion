# C-2 실시간 상품 사진 보충

상품명에 핏·기장 단서가 없는 상위 후보에 기존 사진 분류기를 연결했다. 종류·소재는 C-1에서 보충 오답이 많아 사용하지 않는다. 모델 재학습·체크포인트 교체 없이 배포 서버의 헤드를 재사용한다.

**AI 참조 라벨을 사용한 탐색적 평가다.** 사람이 정답을 작성한 C-1 완료 조건과 별도 표본 검증은 남아 있다. 이 100개를 보고 정책을 설계했으므로 아래 수치를 미지 상품에 대한 정확도나 검증된 확률로 해석할 수 없다. 운영 서버 배포는 이 PR에 포함하지 않는다.

## 실제 처리 기준

- 후보 300개 중 실측 정렬 후 카테고리별 상위 8개까지만 검사한다. 대상은 상의·하의이고, 요청한 핏·기장 축이 상품명에 없어야 한다.
- 요청 키워드뿐 아니라 반대 속성도 검사한다. 예를 들어 상품명에 `슬림`이 있으면 요청이 `와이드`여도 사진으로 덮어쓰지 않는다. 기존 `_score()`의 브랜드 매칭도 우선한다.
- FASHN 실제 분할에서 사람 부위(얼굴·머리·팔·손·다리·몸통)가 이미지의 1% 이상, 해당 의류가 5% 이상인 경우만 착용 흔적이 있다고 본다. 정답 CSV의 컷 라벨을 추론에 입력하지 않는다.
- 헤드가 판정을 수락하고 단일 라벨의 신뢰도가 0.90 이상일 때만 보충한다. `와이드`를 `세미와이드`로 바꾸는 식의 의미 확장은 하지 않는다. 평면컷·불확실한 사진은 보류한다.
- 사진 점수와 상품명 `matched_keywords`를 분리한다. 상품명으로 선택된 상품은 기존 표시 위치를 고정하고, 나머지 자리에서만 사진 점수로 재정렬한다. 실측 정렬과 브랜드 분산을 거친 기준 위치를 사용한다.
- 근거 문구는 `상품 사진에서 '…' 특징이 추정되어 추천 조건을 보충합니다.`이다. LLM이 사진 근거를 상품명 일치로 바꾸면 규칙 문구로 되돌린다.

`web/pipeline.py`가 이미 올린 파서·속성 헤드를 재사용한다. 다운로드는 기존 `_cache_live_shopping_image`를 공유하며 URL까지 캐시 키에 넣고, 디코딩한 픽셀을 PNG로 보존한다. 모델은 기존 분석 잠금 안에서 실행한다. 백그라운드 스레드는 다운로드만 수행한다.

## 같은 100개 전후

상의 34·하의 34·신발 32를 교체하지 않았다. `unknown`과 `not_applicable`은 제외하고, 보류는 일치하지 않은 것으로 센다. 표는 해당 상품이 상위 후보에 들어왔을 때 실제 `_score()`에 사진을 보충한 결과다. 한 검색에서 100개를 모두 추론한 결과가 아니다.

| 축 | 상품명만 | C-2 | 새 일치 / 새 판정 | 새 불일치 |
| --- | ---: | ---: | ---: | ---: |
| item_type | 32/100 | 32/100 | 0/0 | 0 |
| fit | 10/65 (15.4%) | 15/65 (23.1%) | 5/5 | 0 |
| length | 1/54 (1.9%) | 12/54 (22.2%) | 11/11 | 0 |
| material | 17/62 | 17/62 | 0/0 | 0 |

총 281개 평가 가능 속성의 일치는 **60→76, 21.4%→27.0%**다. 제한 없는 보충의 새 불일치 59건을 줄이는 대신 많은 항목을 보류한다. 예측 16개가 모두 맞았다는 사실이 일반적인 오류율 0%를 의미하지 않는다.

상품명에 해당 축의 키워드가 없는 부분집합에서는 핏 **1/52→6/52**, 기장 **0/47→11/47**이다. 종류는 0/62, 소재는 0/42로 그대로다. 전체·키워드 없음·컷별 표 및 400개 개별 판정은 [재생 결과](attribute_c1/c2_accuracy.md)와 [JSON](attribute_c1/c2_accuracy.json)에 있다.

FASHN은 의류 착용컷 59장 중 36장에서 착용 흔적을 확인했고 23장을 보류했다. 의류 평면컷 9장은 모두 보류했다. 신발 32장은 적용 대상이 아니다. 따라서 평면컷의 핏을 맞출 수 있다고 주장하지 않는다. 하의 착용컷의 기장 정답이 모두 긴바지라는 표본 편향도 남아 있다.

## 시간과 순위 검증

동일한 100개 후보 목록을 고정하고 실제 서버 GPU·FASHN·속성 헤드로 세 질의(전체 축, 핏, 기장)를 실행했다. 로컬 원본 사진과 실제 무신사 CDN 다운로드를 각각 사용했다. 검색 API와 실측 조회의 변동을 제외한 실험이며, 각 실행의 `last_search_stats`와 상품 ID를 [원시 측정](attribute_c1/c2_runtime.json)에 보관했다.

사진 다운로드를 실측 조회와 겹쳐 실행하고, 이후 사진 작업 예산은 요청당 0.25초로 둔다. 이미 시작한 GPU 연산은 마칠 때까지 기다리므로 엄격한 0.25초 응답 상한은 아니다. 시간 초과·다운로드 오류·모델 오류는 상품명 결과로 돌아가며, 응답 후 모델 추론이나 상품 점수 변경을 수행하지 않는다. 결과는 상품 ID·사진 URL·카테고리별로 1시간, 최대 512개 캐시한다. 체크포인트를 교체해 엔진을 재구성하면 캐시도 새로 만들어진다.

실제 검색 API·실측 API도 별도로 실행했다. 검색 요청 18개가 모두 성공했고, 상의 519·하의 439·신발 118개를 모아 300·300·118개를 유지했다. 실측은 16개 중 12개에서 확보했다.

| 실제 API 실행 조건 | 상품명만 | C-2 | 차이 |
| --- | ---: | ---: | ---: |
| API·실측·사진 캐시 모두 비움 | 0.9264초 | 1.2627초 | +0.3363초 |
| 캐시 완료 후 3회 중앙값 | 0.0174초 | 0.0177초 | +0.0003초 |

콜드 실행에서 사진 12개 중 8개를 처리하고 4개는 다음 요청으로 보류했다. 사진 단계 자체는 0.2815초였고 캐시 완료 후에는 0.0002초였다. 이 실제 API 질의에서는 신뢰도·상품명 우선 조건을 통과한 사진 보충이 0건이었다. 이 실행을 정확도 개선 사례로 세지 않는다.

콜드 검색은 약 0.34초 늘었다. 따라서 모든 요청에서 지연이 없다고 주장하지 않는다. 장시간 부하나 사용자 체감 기준의 P95 검증까지 수행한 결과도 아니다. 같은 100개를 고정한 실험에서는 사진 단계가 보류한 후보 수까지 저장했다. CDN 첫 실행에서 모든 사진이 늦어 보충을 하나도 하지 못한 경우도 그대로 기록했다.

고정 후보 실험에서 상품명 매칭으로 보호한 **448회 위치 대조 중 순위 하락은 0회**였다. 이는 같은 상품을 여러 실행에서 반복 대조한 수이며 서로 다른 상품 448개라는 뜻이 아니다. 사진 근거는 실제 반환된 상품에도 연결됐고, 기존 상품명 키워드·실측·브랜드 분산 회귀 테스트가 통과했다.

## 재현

추론 체크포인트 SHA-256: `3c560c9db0ade6a62d3ead1fc61edc56ff6a935083ee7393858a3a757431765d`. 배포 중인 `fitta_current`의 파일과 일치함을 다시 확인했다. 원시 결과에 이미지·체크포인트·정책 코드 해시를 기록했다.

네트워크와 GPU 없이 같은 집계를 재생한다.

```bash
python3 ai_fashion_recommender/scripts/evaluate_attribute_c2.py report \
  --labels ai_fashion_recommender/reports/attribute_c1/labels_ai_reviewed.csv \
  --baseline ai_fashion_recommender/reports/attribute_c1/predictions.json \
  --predictions ai_fashion_recommender/reports/attribute_c1/c2_predictions.json \
  --output /tmp/c2_replayed.md
```

사진을 다시 추론하려면 같은 스크립트의 `predict`, 성능을 다시 재려면 `runtime --live-api`를 사용한다. 두 명령은 `--labels`, `--images`, `--checkpoint`, `--expected-sha256`, `--backbone-dir`, `--output`을 요구하며 기본 장치는 CUDA다. 이미지는 C-1의 다운로드 명령으로 확보하고 저장된 SHA-256과 대조한다. `runtime`의 시간 수치는 네트워크·GPU 부하에 따라 달라지며 저장된 판정 표의 재현성과 구분한다.

관련 자동 테스트 **64개**가 통과했다: C-1 측정·참조 검증 14개, 검색 19개, 추천 설명 9개, C-2 정책·캐시·마감·다운로드 중첩 11개, C-2 재생 4개, 웹 연결·이미지 캐시 7개. 정책 테스트는 반대 상품명 우선, 평면컷/낮은 신뢰도 보류, 300개 중 상위 8개 제한, 순위 보존, 실패 격리, URL/TTL 캐시 무효화, 응답 후 추론 금지, 호출 스레드에서만 모델 실행을 검증한다. 저장된 결과를 두 번 집계하면 같은 JSON이 나오며, 체크포인트·중복 ID·임의로 바꾼 판정은 거절된다.
