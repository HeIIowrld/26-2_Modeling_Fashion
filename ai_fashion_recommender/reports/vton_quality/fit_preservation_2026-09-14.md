지금까지의 VTON 평가는 30장을 눈으로 보고 성공/부분 실패/실패로 나눈 것이었다
([batch_eval_after_tiefix.md](batch_eval_after_tiefix.md), [tuning_2026-08-22.md](tuning_2026-08-22.md)).
이번에는 **"레퍼런스 옷의 핏이 결과에 남는가"**를 처음으로 수치로 쟀고, 합성 품질을
사람 눈 없이 재는 지표 여섯 가지와 운영 품질 게이트 세 개의 적중률을 함께 측정했다.

## 설정

**운영과 같은 설정으로 돌렸다.** `CatVTONTryOn.fast()`(DPM++ 2M Karras 25스텝, 시드 42),
augmented 속성 헤드(sha256 `3c560c9d…`), VTON 코드는 배포본 `b930c9b`와 동일함을 diff로 확인.
DSL GPU 서버(RTX 6000 Ada)에서 운영 서비스와 폴더·캐시를 분리해 실행했다.

**사람 12명.** CatVTON 공식 데모 인물 8명 + `datasets/people` 4명. 허리까지만 찍힌 4명은
상의만, 나머지 8명은 상의·하의 둘 다. 원래 옷은 대부분 **몸에 붙는 민소매와 스키니**다.
960×1280 사진 2명(Simon_1, Yifeng_0)은 4절의 버그로 처음엔 전부 실패했고, 수정한 평가용
복사본으로 다시 돌렸다.

**상품 48개.** 정답은 무신사 판매자가 붙인 핏 태그(`detail_fit`)다. 카탈로그 `fit` 칼럼은
우리 속성 모델이 사진에서 읽은 값이라 정답으로 쓰면 순환 논리가 된다. 판매자 태그
4종(슬림·레귤러·여유·오버) × 6개씩, 상의는 아우터 제외, 하의는 긴바지 계열로 뽑았다.
**선택 실수 1건**: 반바지를 한국어 이름으로만 걸러 영문명 반바지 3개가 섞였다
(MS6407706, MS6961597, MS7089046). 기장까지 바뀌므로 핏 지표에서는 빼고 품질 지표에는 넣었다.

**480쌍 + 대조 실험 192쌍.** 쌍당 합성 4.8초, 측정 포함 5.3초.

**신뢰구간은 사람 단위 클러스터 부트스트랩(2000회)**이다. 같은 사람이 24번씩 나오므로
쌍 단위로 뽑으면 구간이 부당하게 좁아진다.

## 1. 핏 보존

### 채점자와 천장

결과 옷의 핏은 운영 속성 헤드(`upper_fit` / `lower_fit`)로 읽었다. 확률을 서열 점수로
바꿨다(슬림 0 · 레귤러 1 · 여유 2 · 오버 3, 하의는 슬림 0 · 테이퍼드·스트레이트 1 ·
플레어 2 · 와이드 3). **채점자 자체가 틀리므로, 같은 채점자가 레퍼런스 사진을 볼 때의
점수를 천장으로 삼고 결과 점수를 그 천장에 견줬다.**

| | 상의 | 하의 |
| --- | --- | --- |
| 천장: Spearman(판매자 태그, 레퍼런스 판정) | 0.71 | **0.24** |
| 결과: Spearman(판매자 태그, 결과 판정) | 0.41 [0.35, 0.47] | 0.25 [0.18, 0.32] |
| 사람 안 평균 Spearman | 0.45 [0.42, 0.50] | 0.27 [0.21, 0.32] |

**하의 채점자는 쓸 수 없다.** 상품 사진에서 판매자 태그를 0.24밖에 못 읽는다. 태그가
엉터리여서가 아니다 — 여유·오버 태그 긴바지 11개 중 10개는 상품명에 '와이드·벌룬·배기'가
있다. 그래서 하의는 분류기 대신 **기하 측정과 대조 실험**으로 판단했다.

### 상의: 절반 남짓 남고, 가운데로 눌린다

**보존율(결과 상관 / 천장 상관) 0.58 [0.50, 0.66].** 태그별로 보면 이렇다.

| 판매자 태그 | 레퍼런스 판정 | 결과 판정 | 원래 옷 판정 |
| --- | --- | --- | --- |
| 슬림핏 | 0.64 | 0.73 | 0.73 |
| 레귤러핏 | 1.37 | 1.06 | 0.73 |
| 여유핏 | 1.55 | 1.08 | 0.73 |
| 오버핏 | 2.12 | **1.37** | 0.73 |

레퍼런스에서 1.48이던 슬림↔오버 간격이 결과에서는 0.64로 줄었다(43%). 오버핏 상의가
여유핏과 레귤러핏 사이 정도로 나온다.

**원래 옷이 샌다.** 결과 판정을 레퍼런스와 원래 옷으로 회귀하면 표준화 계수가
레퍼런스 0.56 / 원래 옷 0.26이다. 결과 argmax가 원래 옷 argmax와 같은 비율(53%)이
판매자 태그와 같은 비율(38%)보다 높다.

**결과를 좌우하는 몫(η²)**: 상품 0.45 · 사람 0.20. 상의는 상품이 더 크게 결정한다.

관찰된 실패 유형 두 가지:
- **소매 누수**: 퍼프 반팔 블라우스를 민소매 차림에 넣으면 민소매로 나온다. 기존에
  알려진 마스크 모양 프라이어와 같은 현상이다.
- **크롭화**: 편집 마스크 안인데도 모델이 배를 맨살로 그린다. 오버핏 후드티가 배꼽 위
  크롭 후드티가 된다. 한 사람(model_7, V넥 민소매)에 몰려 상의 38%에서 원래 옷 자리의
  10% 이상이 맨살이 됐고, 나머지 사람은 0~17%다. 원인은 확인하지 않았다.

### 하의: 폭은 보존되지 않고, 원인은 마스크다

**판매자 태그별 결과 폭**(골반폭 대비 정강이 폭, 사진이 무릎에서 잘린 사람은 허벅지 폭)은
슬림 1.51 · 레귤러 1.54 · 여유 1.53 · 오버 1.52로 **평평하다.** 결과 옷 폭이 마스크 폭의
90% 이상인 쌍이 42%다.

가장 직접적인 검증은 **상품명 라벨**(와이드·벌룬·배기·커브드 13개 vs 나머지 긴바지 8개)로
같은 사람 안에서 결과 폭을 비교한 것이다. 그리고 **하의 마스크만 넓힌 대조 실험**
(행마다 좌우 끝까지 채우고 골반폭의 25%만큼 확장, 같은 쌍·같은 시드)을 함께 돌렸다.

| | 운영 마스크 | 넓힌 마스크 |
| --- | --- | --- |
| 같은 사람 안 (와이드 계열 − 나머지) 결과 폭 | **+0.009 [−0.025, 0.047]** | **+0.093 [0.049, 0.133]** |
| 자기 레퍼런스 식별 top-1 | 0.39 | 0.51 |
| 결과↔레퍼런스 코사인 중앙 | 0.803 | 0.819 |

**운영 마스크에서는 와이드 바지와 슬림 바지의 폭 차이가 0이다. 마스크를 넓히자 차이가
생겼다.** 원래 스키니진을 입은 사람에게 부츠컷·와이드·배기 청바지를 넣으면 모두 스키니로
나온다. 반바지를 입은 Simon_1에게 와이드 벌룬 슬랙스를 넣으면 **반바지 위에 레깅스를 겹쳐
입은 모양**이 된다.

단, 넓힌 마스크는 **슬림 바지도 넓힌다**(여유·오버 +0.27, 슬림·레귤러 +0.19). 모델이
주어진 마스크를 채우는 경향은 그대로이므로, 넓힌 마스크를 그대로 운영에 쓰면 반대 방향
오류가 생긴다. 하의 결과 폭은 사람 몫(η² 0.33)이 상품 몫(0.27)보다 크다.

## 3. 품질 게이트 검증

운영 코드가 합성 전에 내는 경고 세 종류가 실제로 맞는지 봤다.

**아우터 가능성(soft): 48건 전부 오탐.** 민소매를 입은 두 사람(model_5, model_7)의 상의
48쌍 전체에서 원래 옷을 '베스트'로 보고 경고했다. soft 등급이라 마스크는 바꾸지 않지만
사용자에게는 의미 없는 경고가 뜬다. 경고가 난 쌍의 레퍼런스 코사인은 오히려 높았다
(0.841 vs 0.815).

**하의 기장 차이: 15건 중 정답 6건.**
- 정답 6: 긴바지를 입은 2명(049713, model_8) × 반바지 3개.
- 오탐 4: **와이드·벌룬 긴바지 2개**(MS5945210 커브드 슬랙스, MS5308542 벌룬 스웨트팬츠)를
  '쇼츠·미니 기장'으로 판정. 원본 상품 사진에서는 category 헤드가 '팬츠' 0.96 / 0.90이다.
- 오탐 5: **반바지를 입은 Simon_1**의 현재 기장을 '긴바지'로 보고 3단계 차이를 경고.
- 놓침: model_3·model_5·model_7은 사진이 무릎 근처에서 잘려 발목 좌표가 화면 밖인데
  (가시도 0.03), 착장 분석이 '판단 불가' 대신 **'무릎 기장 바지'로 단정**한다. 그래서
  반바지를 넣어도 차이가 1단계로 계산돼 경고가 안 뜬다. 발이 잘린 인스타 사진에서 흔한
  조건이다.

**레퍼런스 해상도 낮음: 하의에서만 쓸모 있다.** 경고 대상은 상품 3개(MS6896829, MS7071476,
MS7091165). 하의 경고 쌍의 레퍼런스 코사인은 0.725 vs 무경고 0.809로 낮았고, 상의는
0.841 vs 0.815로 차이가 없었다. 상의는 상품 1개뿐이라 표본이 작다.

## 4. 발견한 버그: 3:4 사진은 합성이 항상 실패한다

`unpad_result()`([catvton_tryon.py:388](../../src/catvton_tryon.py))는 여백을 덧대지 않은
사진이면 결과를 그대로 돌려준다. 이미 3:4 비율이지만 768×1024가 아닌 사진은 결과가
768×1024로 남고, 이어지는 `_restore_original_regions()`에서 크기가 맞지 않아 `ValueError`로
멈춘다.

로컬에서 GPU 없이 재현했다.

| 입력 크기 | 여백 | 결과 크기 | 보호 영역 복원 |
| --- | --- | --- | --- |
| 768×1024 | 없음 | 768×1024 | 성공 |
| 960×1280 | 없음 | 768×1024 | **실패** |
| 3024×4032 (스마트폰 기본) | 없음 | 768×1024 | **실패** |
| 900×1600 | 있음 | 900×1600 | 성공 |

지금까지 드러나지 않은 이유: 이전 배치 평가가 세로로 긴 인스타 사진(약 1:2)만 써서
항상 여백이 생겼고, 기존 테스트(`test_unpad_is_noop_without_padding`)는 크기가 같은
경우만 검사한다. 웹 업로드는 사진 크기를 줄이지 않는다.

**수정 완료(이 리포트와 같은 커밋).** 여백이 없어도 결과 크기가 원본과 다르면 원본 크기로
되돌린다. 회귀 테스트 `test_matching_aspect_larger_photo_returns_to_original_size`가
960×1280·3024×4032에서 수정 전 실패 → 수정 후 통과함을 확인했다. 평가의 Simon_1·Yifeng_0
96쌍은 같은 수정을 넣은 서버 평가용 복사본으로 다시 돌린 결과다.

## 5. 한계

- **사람 사진이 모델에 유리하다.** CatVTON 공식 데모 인물(스튜디오·정면·단색 배경)이다.
  실사용자 사진이나 팀의 인스타 수집본 102장은 서버에 없어 쓰지 못했다.
- **원래 옷이 한쪽으로 쏠렸다.** 대부분 몸에 붙는 옷이라 "넓은 옷을 입은 사람에게 슬림을
  넣는" 방향은 상의 데모 3명 정도로만 확인됐다.
- **채점자 오차.** 상의 핏 헤드의 검증 정확도 자체가 0.64다. 천장 대비로 봤지만 절대값은
  참고용이다. 상의 가슴 폭은 소매가 몸통 옆에 붙으면 섞여서 보조 지표로만 썼다.
- 사진이 무릎에서 잘린 사람(model_3, model_4, model_5, model_7)은 허벅지 폭으로 대신 쟀다.
- 시드 1개(42), fast 프리셋만.

2. **하의 핏은 지금 구조로는 보여줄 수 없다는 점을 먼저 인정할 것.** 와이드 바지 결과
   화면에 "실제 핏은 원래 입은 바지 모양을 따라갈 수 있음"을 표시하는 게 가장 싸다.
   마스크를 넓히면 차이는 생기지만 슬림 바지도 넓어지므로, 레퍼런스가 와이드 계열일 때만
   넓히는 선택 적용을 같은 방식의 대조 실험으로 검증한 뒤에 도입할 것.
3. **아우터 soft 경고의 민소매 오탐 제거.** 민소매를 '베스트'로 보는 판정을 고치거나,
   소매가 없는 원래 옷에는 soft 경고를 내지 않는다.
4. **기장 게이트 두 곳.** 발목이 화면 밖이면 현재 기장을 '판단 불가'로 두고, 레퍼런스
   기장 판정에서 와이드·벌룬 긴바지를 쇼츠로 보는 오판을 확인한다.
