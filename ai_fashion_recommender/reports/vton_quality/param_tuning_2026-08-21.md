# 추론 파라미터 A/B (2026-08-21)

인수인계 문서의 "튜닝 전에 검토할 만한 대안 1번"을 실행한 기록이다.
모델 가중치는 건드리지 않았다. `scripts/tune_vton.py`로 **같은 사진·같은 시드**에서
파라미터를 **한 번에 하나씩만** 바꿨다.

- 대상: IMG_5455(남), IMG_5497(남), IMG_5383(여·스커트 시스루) — 10개 변종 전부
- 추가 검증: IMG_5413(여), IMG_5483(남), IMG_5390(여) — baseline vs repaint300만
- 재료: `outputs/vton_tuning/` (변종별 폴더, records.json, sheets/)

**표본이 작다(3~6명).** 아래 결론은 방향을 잡는 용도이고, 기본값을 바꾸기 전에
30장 배치로 확인하는 편이 안전하다.

## 결론 요약

| 파라미터 | 판정 |
| --- | --- |
| `repaint_blur_divisor` | **150 → 300으로 바꿨다.** 30장 검증에서 악화 0장, 성공 14 → 15 |
| `num_inference_steps` | 기본값 유지. **`fast()` 프리셋(25스텝)** 추가 — 시간 45% 절감 |
| `guidance_scale` | **바꾸지 말 것.** 텍스처와 시스루가 반대로 움직이는 트레이드오프 |
| `pipeline_mask_blur` | **바꿀 이유 없음.** 3/9/17 사이에 측정 가능한 차이가 없다 |

## 1. `repaint_blur_divisor` — halo를 지배하는 손잡이

블렌딩 반경은 `height // divisor`다. divisor가 클수록 밴드가 좁다.

IMG_5497은 원래 **빨간** 스웨트를 입었고 **검정** 반팔로 바꿨다. 어깨 영역에
남는 붉은기가 곧 halo다.

| divisor | 붉은기 평균 | 붉은 픽셀 비율 |
| --- | --- | --- |
| 75 (밴드 넓음) | 15.87 | **21.1%** |
| 150 (현재 기본값) | 10.62 | 10.7% |
| 300 (밴드 좁음) | **9.10** | **9.5%** |

다른 변종은 전부 10.3~10.7% 부근이다. 즉 **halo는 이 파라미터에만 반응한다.**

육안으로도 일관된다. 추가 3명에서 baseline에 있던 아티팩트가 repaint300에서 사라졌다.

- IMG_5413 — 오른쪽 세로로 서 있던 **흰 띠가 없어졌다** (배치 판정에서 부분 실패 사유였다)
- IMG_5483 — 팔 주변 회색 잔상이 뚜렷하게 줄었다
- IMG_5390 — 몸 오른쪽 윤곽 잔상이 줄었다
- IMG_5455 — 벽에 비치던 원래 티셔츠 실루엣 잔상이 가장 옅다

6명 중 **더 나빠진 경우는 없었다.** 시간 비용도 없다(둘 다 약 44초).

2026-08-20에 도입한 `repaint_inset`과 같은 방향이다. 그때 밴드를 마스크 안쪽으로
옮겼고, 이번엔 그 밴드를 더 좁히는 것이다.

## 2. `num_inference_steps` — 품질보다 시간 문제

| steps | 장당 시간 | 육안 |
| --- | --- | --- |
| 25 | **24.5초** | 청바지 질감이 약간 평평하지만 쓸 만하다 |
| 50 (기본값) | 44.0초 | 기준 |
| 75 | 65.4초 | 50과 구분하기 어렵다 |

25 → 50에서 얻는 것보다 50 → 75에서 얻는 게 훨씬 적다. **75는 값을 못 한다.**
30장 배치를 25 스텝으로 돌리면 약 22분에서 약 12분으로 줄어든다.
데모용 최종본은 50을 유지하고, 반복 평가는 25로 돌리는 운용을 권한다.

## 3. `guidance_scale` — 시스루가 여기에 반응한다 (새 발견)

`reports/vton_quality/README.md`의 시스루 조사는 가설 5개를 기각하고 "시드 무관"까지
확인했지만 **guidance_scale은 시험한 적이 없다.** 이번에 걸렸다.

IMG_5383 스커트 안쪽에서 잰 값이다. 천이 불투명하면 안이 균일하고, 비치면 다리
윤곽이 구조로 남아 두 지표가 함께 오른다.

| guidance_scale | 밝기 표준편차 | 엣지 에너지 |
| --- | --- | --- |
| 1.5 | **38.41** | **1.695** |
| 2.5 (기본값) | 43.30 | 1.841 |
| 3.5 | 44.59 | 1.989 |
| 5.0 | 45.75 | 2.300 |

**두 지표 모두 완전히 단조 증가한다.** 육안으로도 cfg1.5가 가장 불투명하고
cfg5.0에서 다리 윤곽이 가장 뚜렷하다.

해석: guidance를 올릴수록 레퍼런스 조건을 강하게 따라가는데, 레퍼런스가 착용컷에서
잘라낸 얇은 조각이면 그 얇음까지 따라간다. 낮추면 모델이 "보통의 불투명한 옷"이라는
사전 지식 쪽으로 물러선다.

**다만 반대 방향의 대가가 있다.** IMG_5497 청바지에서 cfg를 올릴수록 데님 질감과
대비가 살아난다. cfg1.5는 눈에 띄게 평평하다.

즉 **텍스처 충실도와 시스루가 같은 손잡이의 양쪽 끝**이다. 어느 쪽을 살지는
제품 판단이고, 표본 1장으로 정할 문제가 아니다. 기본값 2.5를 유지한다.

시스루 상품을 따로 감지할 수 있다면 **그 상품에만 guidance를 낮추는** 선택적 처리가
가능하다. 다만 시스루 예측기는 아직 없다.

## 4. `pipeline_mask_blur` — 손대지 말 것

3 / 9(기본값) / 17에서 halo 지표가 10.6% / 10.7% / 10.6%로 사실상 같다.
육안 차이도 옷 주름 모양이 조금 달라지는 정도이고 좋아지는 방향이 아니다.
2026-08-20에 halo 원인이 이쪽이 아니라 repaint 밴드였다고 규명한 것과 일치한다.

## 적용과 30장 검증

`repaint_blur_divisor` 기본값을 **150 → 300으로 바꿨고**
([catvton_tryon.py](../../src/catvton_tryon.py)), 같은 30장을 다시 돌려 확인했다.
바꾼 변수는 이것 하나뿐이고 사진·시드·추천은 모두 같다.
재료는 `outputs/batch_eval_repaint150/`과 `outputs/batch_eval_repaint300/`에 갈라 뒀다.

| 판정 | repaint150 | repaint300 |
| --- | --- | --- |
| 성공 | 14 | **15** |
| 부분 실패 | 13 | 12 |
| 실패 | 2 | 2 |
| 경고 발생 | 21/29 | 21/29 |
| 장당 시간 | 86초 | 89초 |

**판정이 바뀐 건 IMG_5413 한 장**이다. 스커트 오른쪽에 세로로 서 있던 흰 띠가
완전히 사라져 부분 실패에서 성공이 됐다.

판정을 넘기지는 못했지만 결함이 줄어든 장이 여럿이다. 29장 중 **더 나빠진 장은 없다.**

| 사진 | 달라진 점 |
| --- | --- |
| IMG_5497 | 어깨의 빨강 잔류가 뚜렷하게 줄었다 |
| IMG_5531 | 상의 아래 흰 소매 잔류가 사라졌다 (기장 문제는 남아 부분 실패 유지) |
| IMG_5494 | 팔의 초록 잔류가 줄었다 |
| IMG_5455 · IMG_5483 · IMG_5487 · IMG_5507 · IMG_5518 · IMG_5394 | 원래 옷 실루엣 잔상이 옅어졌다 |

두 결과의 픽셀 차이는 평균 2.9%(최소 0.7% / 최대 7.9%)로, 경계 밴드만 바뀌었다는
예상과 맞는다. 시간 비용도 사실상 없다(86초 → 89초).

### 시스루는 이 값과 무관하다

시트에서 스커트가 덜 비쳐 보이는 듯했으나 **수치로는 차이가 없었다.**

| 사진 | repaint150 | repaint300 |
| --- | --- | --- |
| IMG_5383 표준편차 / 엣지 | 43.64 / 1.852 | 44.08 / 1.835 |
| IMG_5534 표준편차 / 엣지 | 39.93 / 6.698 | 35.02 / 7.264 |

방향이 엇갈리고 크기도 작다. 시스루는 `guidance_scale` 쪽 문제이고 여기서는 안 움직인다.

### `num_inference_steps`는 기본값을 그대로 뒀다

품질과 시간의 맞교환이라 기본값으로 강제할 성질이 아니다. 대신
`CatVTONTryOn.fast()` 프리셋(25스텝)을 추가하고 `batch_eval.py --fast`로 붙였다.
반복 평가는 이걸로 돌리고, 데모용 최종본은 기본값(50)으로 다시 뽑는다.

## 이 튜닝으로 못 고치는 것

배치 재평가에서 남은 실패 15장 중 8장이 **아우터 착용 사진**이다
([batch_eval_after_tiefix.md](batch_eval_after_tiefix.md)). 마스크가 원래 옷 기준으로
만들어지는 구조적 문제라 **어떤 추론 파라미터로도 바뀌지 않는다.**
10개 변종 전부에서 동일하게 남았다.

## 재현 방법

```bash
cd ai_fashion_recommender
<vton python> scripts/tune_vton.py --list
<vton python> scripts/tune_vton.py --images IMG_5455,IMG_5497,IMG_5383 \
    --variants baseline,cfg3.5 --skip-existing
```

포그라운드로 돌릴 것. 백그라운드로 띄우면 모델 로드 직후 멈춘다(4회 재현).
한 번에 오래 못 돌리면 `--variants`로 나누고 `--skip-existing`으로 이어서 돌린다.
