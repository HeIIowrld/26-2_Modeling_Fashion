# 핏 기반 몸선 prior와 VTON 연동

## 목적

와이드 팬츠나 오버핏 상의의 외곽선을 사용자의 실제 몸 외곽선으로 취급하면, 새 상품도
원래 옷의 폭과 기장을 따라 생성된다. 이 변경은 현재 착장의 핏 라벨, 포즈 관절과 FASHN
파싱을 사용해 숨겨진 몸의 **위치 범위**를 보수적으로 추정하고, 기존 CatVTON·FLUX 전환
경로가 필요한 경우를 결정한다.

이 결과는 실제 신체 치수나 복원된 정답 몸선이 아니다. `confidence`와 픽셀 맵은 현재
데이터에서 보정된 확률이 아니며 생성 마스크를 위한 내부 신호로만 사용한다.

## 출력

`src/body_shape_prior.py`의 `BodyShapePrior`는 다음 세 출력을 만든다.

| 출력 | 의미 | 사용처 |
|---|---|---|
| `central_mask` | 관절 중심의 가장 가능성 높은 내부 영역 | 디버그·후속 공간 조건 |
| `plausible_mask` | 핏에 따라 넓힌 가능한 몸 위치 범위 | 기존 전환 편집 영역과 결합 |
| `confidence_map` | 중심과 불확실 영역을 구분한 비보정 신뢰도 | 품질 보고·후속 생성 조건 |

상의는 어깨·골반과 팔 관절, 하의는 골반·무릎·발목을 사용한다. 여러 사람이 파싱된
사진에서는 관절이 닿는 연결 성분만 선택한다. 필수 관절이 없으면 추정을 만들지 않고
기존 생성 경로로 돌아간다.

## 핏 규칙

| 현재 착장 | 목표 상품 | 처리 |
|---|---|---|
| 오버 | 레귤러·슬림 | 기존 FLUX 전환 편집 사용 |
| 와이드·세미와이드 | 스트레이트·슬림 | 기존 FLUX 전환 편집 사용 |
| 레귤러·스트레이트 | 오버·와이드 | 검증된 CatVTON 마스크 정책 유지 |
| 와이드 | 세미와이드 | 과도한 축소를 피하고 기존 정책 유지 |

상품명뿐 아니라 `Product.fit`을 우선 사용한다. 따라서 이름에 `스키니`가 없어도 구조화된
핏이 `슬림핏`이면 기존 `long-hull` 확장을 적용하지 않는다. 상의 레이어드 사진은 가장
바깥쪽으로 관측된 핏을 사용하되 prior 신뢰도를 낮춘다.

## 기존 기능 재사용

- `agnostic_upper_mask`: 원래 상의의 넥라인·밑단 단서 제거
- `long_bottom_mask`: 긴 바지용 하체 편집 공간과 신발 윗부분 보호 해제
- `transition_envelope`: 원래 옷 전체와 주변 배경을 편집할 공간 확보
- FLUX 전환 편집: 좁아지거나 짧아진 옷에서 피부·배경을 함께 복원
- repaint·원본 보호·품질 검사: 편집 영역 밖 얼굴·손·가방·신발 보존

prior 자체를 실제 신체로 그려 넣지는 않는다. 핏이 좁아지는 경우를 찾아 전환 편집을
발동하고, 가능한 몸 위치 범위를 전환 마스크에 포함하며, 프롬프트에는 원래 옷 부피를
보존하지 말라는 조건을 추가한다.

## 검증 상태

- 새 prior·핏 어휘·레이어드 신뢰도·관절 누락 폴백 단위 테스트
- `와이드 → 스트레이트`가 기존 FLUX 전환 편집으로 분기되는 통합 테스트
- 구조화된 `슬림핏` 상품이 하체 `long-hull` 확장에서 제외되는 회귀 테스트
- CPU 대상 테스트 19개 통과

현재 Windows 작업 환경에는 CatVTON·FLUX 로컬 체크포인트와 전체 VTON 선택 의존성이
없어 실제 생성 A/B는 아직 실행하지 않았다. 실제 배포 전에는 같은 사람·상품·시드에서
prior 비활성/활성 결과를 비교하고, 몸 비율 보존·상품 핏·마스크 밖 픽셀 보존 기준을
통과해야 한다.
