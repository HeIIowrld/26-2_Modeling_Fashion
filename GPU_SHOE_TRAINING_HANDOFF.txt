======================================================================
0. 가장 먼저 확인할 점
======================================================================

현재 신발 인식은 "학습 가능한 헤드와 웹 추론 연결부"까지만 구현되어 있다.
실제 신발 데이터, 학습 완료 가중치, 데이터 전처리 CLI, 전체 학습 CLI는 아직 없다.
GPU PC에 데이터만 복사한다고 바로 학습되는 상태는 아니며, 아래 계약대로 두 학습 스크립트를
먼저 구현해야 한다. 구현 전에는 라벨 순서와 crop 정책부터 확정한다.

따라서 GPU PC에서는 다음 두 파일을 추가로 만드는 작업이 먼저 필요하다.

1) scripts/prepare_shoe_dataset.py
   - 전신사진에서 FASHN segmentation의 feet(15) 영역을 crop
   - crop과 라벨을 저장
   - FashionSigLIP 임베딩을 캐시

2) scripts/train_shoe_heads.py
   - 캐시된 train/validation 임베딩을 읽음
   - src/shoe_model.py의 신발 헤드를 학습
   - 검증 세트로 confidence threshold를 결정
   - models/shoe_heads.pt로 저장

기존 scripts/train_fashion_attribute_heads.py는 상의·하의 속성 전용이다.
현재 상태에서 해당 스크립트에 신발 데이터를 바로 넣으면 안 된다.
신발 헤드는 기존 의류 헤드 체크포인트와 별도로 유지한다.

이 가이드를 포함한 브랜치를 GPU PC에서 clone/pull한다. 데이터와 학습 체크포인트는 용량·저작권
문제 때문에 Git에 넣지 않는다. 데이터 원본 경로, manifest, metrics, 체크섬만 별도 보관한다.

1. 지금까지 반영한 기능
======================================================================

[웹 입력]
- 기존 상의/하의/둘 다 드롭다운을 제거했다.
- 상의(top), 하의(bottom), 신발(shoes)을 독립 체크박스로 선택한다.
- 하나 이상의 카테고리를 반드시 선택한다.
- 성별(남성/여성)을 필수 선택으로 추가했다.
- 무신사 검색은 선택 성별 상품과 공용 상품만 허용한다.

[무신사 검색 및 코디 조합]
- 무신사 신발 대분류 코드 103을 연결했다.
- 선택한 카테고리별 후보를 최대 6개 검색한 뒤 Fashion Rules 조화 점수로 코디 조합 3개를 만든다.
- 예: 상의+신발 변경이면 현재 하의를 고정하고 상의 1개+신발 1개를 묶은 LOOK 3개를 추천한다.
- 특정 카테고리 결과가 부족해도 다른 카테고리 상품으로 억지로 채우지 않는다.
- 신발 검색 키워드는 사용자 목적, 원하는 스타일, 색상, 계절/활동 조건으로 생성한다.
- 신발에는 체형이나 다리 길이 보정 규칙을 적용하지 않는다.
- 신발 추천 이유에서도 체형 보정을 근거로 사용하지 않는다.
- 신발 가상 피팅은 전용 모델 체크포인트가 준비된 경우에만 실험 기능으로 활성화한다.
- 의류 CatVTON의 하의 마스크로 신발을 잘못 합성하지 않는다.

[신발 인식]
- src/shoe_model.py에 FashionSigLIP 임베딩용 독립 MLP 헤드를 추가했다.
- FASHN Parser의 feet(15) segmentation bbox를 신발 crop으로 사용한다.
- 학습 체크포인트가 없으면 임의 예측하지 않고 not_trained를 반환한다.
- 발 영역이 너무 작거나 보이지 않으면 not_visible을 반환한다.
- confidence가 임계값보다 낮으면 uncertain으로 보류한다.
- 맨발과 기타 신발은 confidence가 높아도 실제 신발 종류로 accepted 처리하지 않는다.
- 학습된 결과는 OutfitAnalysis.shoes와 웹의 '내 착장 분석 > 현재 착장 > 신발'에 표시된다.

[기존 기능 호환]
- 기존 의류 ATTRIBUTE_TASKS와 의류 체크포인트 스키마를 변경하지 않았다.
- 기존 main.ipynb의 change_scope 호출은 호환된다.
- 새 호출은 UserProfile(change_categories=["top", "bottom", "shoes"]) 형식을 우선한다.
- 기존 상의/하의 2x3 현재 코디 점수표는 유지한다. 신발은 체형 점수표에 넣지 않았다.

[LLM 추천 이유 설정]
- 저장소 루트의 .env를 서버 시작 때 자동으로 읽는다.
- API 키는 Git에서 제외하며 로그에 출력하지 않는다.
- Gemini에는 서버가 검증한 적용 규칙과 상품명 매칭 키워드만 전달한다.
- 코디 조합의 순위는 규칙 기반 코드가 결정하고 LLM은 근거를 자연스러운 한 문장으로 다듬는다.
- 예산·가격·할인·가성비 등 금액을 언급한 문장은 규칙 기반 문장으로 대체한다.
- 신발 추천에는 체형이나 다리 길이를 근거로 사용하지 않는다.
- .env.example은 설정 형식만 제공하고 실제 키를 포함하지 않는다.

3. 현재 신발 헤드의 정확한 학습 계약
======================================================================

백본 모델 ID
- Marqo/marqo-fashionSigLIP
- config.py의 FASHION_SIGLIP_MODEL_ID와 같아야 한다.
- 백본은 freeze하고 신발 헤드만 학습한다.

전처리
- preprocessing 메타데이터는 squash다.
- 추론에서는 기존 FashionClassifier._encode_image()의 FashionSigLIP preprocess를 쓴다.
- 학습과 추론에서 crop 정의와 preprocess가 반드시 같아야 한다.

현재 분류 라벨과 순서(SHOE_LABELS)
0  스니커즈
1  러닝화
2  로퍼
3  더비슈즈
4  메리제인
5  펌프스
6  샌들
7  슬리퍼
8  부츠
9  워커
10 기타 신발
11 맨발

라벨 순서를 바꾸면 기존 체크포인트와 호환되지 않는다.
새 라벨을 추가해야 한다면 SHOE_CHECKPOINT_VERSION을 올리고 마이그레이션해야 한다.

헤드 구조
- LayerNorm(input_dim)
- Linear(input_dim -> 256)
- GELU
- Dropout(0.15)
- Linear(256 -> 12 classes)

손실 함수
- CrossEntropy
- label -1은 미라벨 표본으로 loss에서 제외한다.
- 배치가 전부 -1이면 의도적으로 오류를 낸다.

체크포인트 필수 메타데이터
- version
- labels
- backbone_model_id
- preprocessing="squash"
- input_dim, hidden_dim, dropout
- training_examples
- threshold
- state_dict

권장 폴더 예시

datasets/shoes/

    ut_zap50k/
    aihub/
    modanet/
    lip/
    deepfashion_multimodal/
    consented_own/
  crops/                   shoe_crop으로 만든 양발 crop
  annotations.csv
  rejected.csv             crop 실패·가림·라벨 불일치 표본
  dataset_card.md          출처/라이선스/버전/수량/담당자
  caches/
    train.pt
    val.pt
    test.pt

annotations.csv 권장 컬럼

image_path,crop_path,source,source_id,subject_id,session_id,product_id,shoe_label,split,quality,license,notes

예시
source/a.jpg,crops/000001.jpg,own,OWN0001,P001,S001,SKU001,스니커즈,train,ok,consented,
source/b.jpg,crops/000002.jpg,modanet,12345,P002,S004,SKU015,로퍼,val,ok,CC-BY-NC-4.0,바짓단 일부 가림

필수 원칙
1) 전신 착장 사진을 반드시 포함한다.
   상품 단독 사진만 학습하면 실제 사용자 사진의 작은 신발, 바짓단 가림, 배경 때문에 성능이 크게 떨어진다.
2) 같은 사람, 촬영 세션, 동일 상품은 train/val/test에 나누어 넣지 않는다.
   최소한 subject_id와 product_id를 기준으로 group split한다.
3) 맨발, 양말만 보임, 신발이 잘림, 발이 가려짐, 매우 작은 신발도 수집한다.
4) 신발 종류별 표본 수를 가능한 한 균형 있게 맞춘다.
5) 성별은 추천 상품 필터용 정보다. 신발 종류 헤드의 정답 라벨로 사용하지 않는다.
6) 검증/테스트 데이터는 학습 중 augmentation이나 threshold 선택에 사용하지 않는다.
7) 원본 URL 대신 source의 공식 ID와 이용조건을 기록한다. 이미지 파일 자체는 Git에 넣지 않는다.
8) 동일/근접 중복 이미지는 pHash로 제거하고, 같은 상품·사람은 하나의 split에만 둔다.

권장 초기 규모(절대 기준은 아님)
- 파이프라인 확인용 pilot: 클래스당 100~200개 이상의 유효 착장 crop
- 실제 성능 개선용: 클래스당 500개 이상을 목표로 하고, 성능 곡선을 보고 추가 수집
- 희소 클래스는 무리하게 복제하기보다 balanced sampler와 추가 수집을 우선한다.

현재 shoe_crop의 한계
- FASHN의 15번은 '신발 전용'이 아니라 feet 영역이므로 맨발도 포함한다.
- 현재 bbox는 양발을 한 박스로 묶고 여백을 추가하지 않는다.
- crop 정책을 바꿀 경우 학습과 추론의 shoe_crop을 동시에 수정해야 한다.
- 신발이 너무 작으면 현재 조건(len(xs)<64, 폭/높이<8px)에서 not_visible이 된다.

4-A. 비영리 연구용 대규모 데이터 확보처
======================================================================

핵심 전략
- 상품 단독 신발 사진: 종류의 모양을 배우는 사전학습/워밍업 데이터로 사용한다.
- 실제 전신 착장 사진: 작은 신발, 바짓단 가림, 배경, 조명에 적응하는 주 학습 데이터로 사용한다.
- 최종 validation/test: 반드시 학습에 없던 사람과 신발 상품의 실제 전신 착장 사진으로 만든다.
- 공개 데이터의 원본 이미지는 저장소에 commit하거나 다시 배포하지 않는다.
- 각 데이터셋의 최신 이용약관을 다운로드 당일 다시 확인하고, 출처/버전/다운로드일을 기록한다.

[1순위] UT Zappos50K: 신발 종류 사전학습
- 공식: https://vision.cs.utexas.edu/projects/finegrained/utzap50k/
- 규모: 상품 단독 신발 이미지 50,025장.
- 큰 분류: shoes, sandals, slippers, boots. 세부 functional type과 메타데이터가 있다.
- 이용 조건: 공식 페이지에 ACADEMIC USE ONLY, academic/non-commercial use only로 명시되어 있다.
- 장점: 신발이 크고 배경·방향이 일정해 12종 형태를 빠르게 학습시키기 좋다.
- 한계: 흰 배경 상품 사진이라 실제 전신사진 도메인과 크게 다르다. 이것만으로 최종 헤드를
  학습하면 안 되고, 전체 학습 샘플의 20~30% 이하 또는 초기 warm-up 용도로 제한한다.
- 다운로드: 공식 페이지의 ut-zap50k-images.zip과 메타데이터를 직접 받는다. 제3자 Kaggle/HF
  미러보다 공식 아카이브를 우선한다.

[1순위] AI Hub '의류 가상착용 3D 이미지': 국내 착용/상품 데이터 후보
- 공식: https://www.aihub.or.kr/aihubdata/data/view.do?aihubDataSe=realm&dataSetSn=75
- 공식 설명상 상의·하의·신발·모자·액세서리 상품을 포함하고, 2D/3D 신체 및 착용/미착용
  상품 데이터를 대규모로 제공한다. 2D 학습 세트만 신체 약 101만 장, 착용 상품 약 69만 장,
  미착용 상품 약 111만 장으로 안내되어 있다.
- 장점: 국내 서비스 도메인과 가깝고 착용/미착용 데이터를 같이 확보할 가능성이 높다.
- 주의: 온라인 안심존/신청 절차와 반출 조건이 적용될 수 있다. GPU 장비로 원본을 가져갈 수
  있는지, 신발 세부 종류 라벨이 실제 JSON에 있는지 샘플·설명서를 먼저 확인한다.
- 세부 12종 라벨이 없다면 신발 영역 crop 생성용으로만 쓰고 별도 사람 검수 라벨을 붙인다.

[2순위] ModaNet: 실제 거리 착장 적응
- 공식: https://github.com/eBay/modanet
- 규모: 약 55,176장의 street-fashion 이미지에 polygon/bbox가 있다.
- 신발 라벨: boots와 footwear 두 종류만 제공한다.
- 이용 조건: annotation은 CC BY-NC 4.0. 원본은 PaperDoll/Chictopia 이미지이므로 이미지의
  별도 이용조건도 확인해야 한다.
- 사용법: boots/footwear polygon으로 신발 crop을 뽑은 뒤 FITTA 12종으로 사람이 재라벨링한다.
- 장점: 실제 착장, 작은 신발, 가림, 복잡한 배경을 포함해 도메인 적응용으로 가치가 높다.
- 한계: boots/footwear만으로는 스니커즈·로퍼 등을 자동 구분할 수 없다.

[2순위] LIP (Look Into Person): 발 위치와 가림 조건 적응
- 공식 프로젝트: http://www.sysu-hcp.net/lip/
- 논문: https://arxiv.org/abs/1804.01984
- 규모: 50,000장 이상의 single-person 실세계 이미지로 알려져 있다.
- left-shoe/right-shoe human-parsing 라벨이 있어 양발 영역을 찾는 데 유용하다.
- 신발 종류 라벨은 없으므로 crop 후 사람이 12종을 붙여야 한다.
- 공식 배포처의 현재 이용조건을 확인한 뒤 비영리 연구 범위에서 사용한다.

[2순위] DeepFashion-MultiModal: 고품질 전신 이미지 적응
- 공식: https://github.com/yumingj/DeepFashion-MultiModal
- 계약: https://github.com/yumingj/DeepFashion-MultiModal/blob/main/LICENSE

4-B. FITTA 12종 라벨 매핑 기준
======================================================================

0 스니커즈
- 일상/라이프스타일 운동화. 캔버스화, 코트화, 패션 스니커즈 포함.

1 러닝화
- 출처 메타데이터가 running으로 명시되거나 러닝용 기능화임이 확실한 경우만 사용한다.
- 단순히 스포티하게 생겼다는 이유로 러닝화 라벨을 붙이지 않는다.

2 로퍼
- 끈 없이 발등을 덮는 slip-on 정장화. 페니/태슬/비트 로퍼 포함.

3 더비슈즈
- open-lacing 구조의 포멀 레이스업을 원칙으로 한다.
- Oxford를 같은 서비스 라벨로 합칠지 학습 전에 팀에서 결정한다. 합치지 않으면 Oxford는 기타 신발.

4 메리제인
- 발등 스트랩이 분명한 Mary Jane. 굽 높이는 무관하다.

5 펌프스
- 발등이 열리고 앞·뒤가 닫힌 구두형 여성화. Mary Jane 스트랩이 있으면 메리제인으로 보낸다.

6 샌들
- 스트랩/오픈토 구조이며 뒤꿈치 고정 구조가 있는 경우를 우선한다.

7 슬리퍼
- 뒤꿈치 고정 없이 쉽게 신고 벗는 slide/flip-flop/실내용 slipper.

8 부츠
- ankle/Chelsea/knee/high boots 등 일반 부츠.

9 워커
- combat/work/hiking 계열처럼 두꺼운 밑창·레이스업·보호 구조가 분명한 부츠.

10 기타 신발
- 위 10종에 안정적으로 들어가지 않는 clog, aqua shoes, 특수 작업화, 혼합형 등.
- 품질 불량/가림 표본을 기타 신발로 보내지 않는다. 그런 표본은 quality=reject로 별도 제외한다.

11 맨발
- 맨발과 양말만 착용한 경우. predictor에서 실제 신발로 accepted되지 않는 안전 음성 클래스다.

애매한 표본 처리
- 좌우 신발 종류가 다름: 기본적으로 reject 또는 기타 신발. 한쪽 라벨을 임의로 고르지 않는다.
- 발이 잘리거나 70% 이상 가림: quality=reject. 학습에서는 제외하고 별도 stress test에 둔다.
- 라벨러가 확신하지 못함: label=-1/needs_review. 다수결 또는 선임 검수 후 확정한다.
- 같은 이미지의 좌우 반전/색변환은 같은 split 안에서만 생성한다.

======================================================================
4-C. 권장 데이터 물량과 혼합 비율
======================================================================

파일럿
- 실제 착장 crop: 클래스당 300장 이상
- validation: 클래스당 80장 이상
- test: 클래스당 100장 이상, 사람과 상품 모두 train과 중복 금지

1차 서비스 목표
- 실제 착장 crop: 주요 클래스 2,000~5,000장, 희소 클래스 최소 800~1,500장
- 상품 단독 crop: 클래스당 최대 3,000장만 사용해 catalog 도메인이 학습을 지배하지 않게 한다.
- 맨발: 최소 2,000장. 기타 신발: 최소 1,000장.
- reject/stress set: 가림·저해상도·검정 배경 등 최소 2,000장.
- 전체 권장 규모: 검수 완료 착장 crop 20,000~40,000장부터 시작해 오류 곡선을 보고 추가한다.

권장 학습 혼합
- 1단계 warm-up: UT Zappos 등 상품 단독 이미지, 1~3 epoch.
- 2단계 mixed: 실제 착장 70~80%, 상품 단독 20~30%로 10~20 epoch.
- 3단계 domain finish: 실제 착장과 hard case만 사용해 3~8 epoch.
- synthetic 합성 이미지는 train의 20%를 넘기지 않고 validation/test에는 절대 넣지 않는다.

======================================================================
7. 헤드 학습 루프 권장값
======================================================================

시작값
- optimizer: AdamW
- learning rate: 1e-3
- batch size: 128 (메모리에 맞게 조절)
- epochs: 최대 30
- hidden_dim: 256
- dropout: 0.15
- early stopping: validation macro-F1 기준 patience 5
- seed: 최소 3개 seed 결과를 함께 기록
- mixed precision: torch.autocast + GradScaler 권장
- gradient clipping: 1.0
- scheduler: ReduceLROnPlateau 또는 cosine decay 중 하나를 고정하고 기록

핵심 인터페이스

from shoe_model import build_shoe_heads, shoe_classification_loss

heads = build_shoe_heads(
    input_dim=train_features.shape[-1],
    hidden_dim=256,
    dropout=0.15,
).to("cuda")

optimizer = torch.optim.AdamW(heads.parameters(), lr=1e-3)

for features, labels in train_loader:
    features = features.to("cuda")
    labels = labels.to("cuda")
    heads.train()
    optimizer.zero_grad(set_to_none=True)
    logits = heads(features)
    loss = shoe_classification_loss(logits, labels)
    loss.backward()
    optimizer.step()

클래스 불균형이 크면 먼저 WeightedRandomSampler 또는 균형 배치를 사용한다.
현재 shoe_classification_loss에는 class weight 인자가 없으므로, 가중 loss가 필요하면
함수 시그니처와 테스트를 함께 변경한다.

train_shoe_heads.py가 가져야 할 최소 CLI 계약

python ai_fashion_recommender/scripts/train_shoe_heads.py \
  --cache-dir "$FITTA_SHOE_DATA/caches" \
  --output ai_fashion_recommender/models/shoe_heads.pt \
  --report-dir "$FITTA_SHOE_DATA/reports/run_001" \
  --epochs 30 \
  --batch-size 128 \
  --learning-rate 1e-3 \
  --hidden-dim 256 \
  --dropout 0.15 \
  --seeds 17 42 2026 \
  --device cuda

이 CLI는 현재 저장소에 아직 없으므로 GPU 학습 전에 구현해야 한다. 구현 완료 기준은 다음과 같다.
- train 캐시로만 optimizer를 갱신한다.
- validation macro-F1로 early stopping/best epoch를 고른다.
- seed별 결과와 평균±표준편차를 저장한다.
- 최종 threshold는 validation prediction으로만 고른다.
- test는 모델·threshold가 확정된 뒤 한 번 평가한다.
- best state_dict만 save_shoe_checkpoint로 저장한다.
- 학습 재개용 optimizer checkpoint와 서비스용 shoe_heads.pt를 분리한다.

8. 검증과 confidence threshold 결정
======================================================================

반드시 기록할 지표
- 전체 accuracy
- macro-F1
- 클래스별 precision / recall / F1 / support
- confusion matrix
- 맨발을 실제 신발로 accepted한 비율
- 기타 신발을 특정 신발로 accepted한 비율
- 신발이 보이지 않거나 잘린 사진의 오작동
- confidence threshold별 accepted coverage와 accepted precision

검증 세트에서 각 예측의 max softmax confidence를 계산한다.
threshold를 올리면 오답은 줄지만 판단 보류가 늘어난다.
초기 목표 예시는 accepted precision 85% 이상이지만, 실제 서비스 목표에 맞춰 결정한다.
threshold는 validation으로 정하고 test set에서는 한 번만 최종 평가한다.

반드시 따로 볼 실패 조건
- 와이드/롱 팬츠가 신발을 많이 가림
- 두 발이 서로 다른 각도 또는 한쪽만 보임
- 작은 전신사진과 저해상도
- 검정 신발과 검정 바닥
- 강한 그림자/역광/색조 조명
- 부츠 vs 워커, 스니커즈 vs 러닝화, 로퍼 vs 더비슈즈 혼동
- 샌들/슬리퍼/맨발 혼동

실제 사진 QA

5) 여성 선택 시 남성 전용 상품이 나오지 않는지 확인한다.
6) 공용 상품은 양쪽에 나오는지 확인한다.
7) 신발만 체크하면 서로 다른 신발 상품을 사용한 LOOK이 최대 3개 나오는지 확인한다.
8) 상의+신발이면 현재 하의를 유지한 상의 1개+신발 1개 조합이 최대 3개인지 확인한다.
9) 신발 추천 이유에 체형/다리 길이 보정 문구가 없는지 확인한다.
10) 신발 전용 VTON이 없을 때 신발을 CatVTON 하의 합성 대상으로 잘못 넣지 않는지 확인한다.

12. 현재 테스트 및 알려진 제한
======================================================================

현재까지 확인한 내용
- 신발 헤드 생성, 역전파, 체크포인트 round-trip 테스트
- 맨발 accepted 방지
- 기존 의류 체크포인트 스키마 불변
- 상의/하의/신발 체크 7개 조합
- 현재 착장과 교체 상품을 묶은 코디 조합 최대 3개 반환
- 신발 키워드의 체형 독립성
- 신발 추천 이유의 체형 표현 제외
- 성별 프로필 전달과 무신사 성별/공용 필터
- 웹 JavaScript 문법 및 Python 문법
- 실제 무신사 category=103에서 신발 상품 응답 확인

알려진 제한
- 신발 가중치는 아직 없다.
- 학습 데이터 로더/캐시/훈련 CLI는 아직 없다.
- FASHN feet mask가 신발 종류를 직접 구분하는 것은 아니다.
- 신발 crop은 양발을 함께 포함한다.
- 작은 신발과 바짓단 가림에서 crop 품질이 낮을 수 있다.
- 신발 가상 피팅은 별도 모델 체크포인트가 있을 때만 활성화되는 실험 기능이다.
- 무신사 상품 성별 메타데이터가 공용으로 잘못 기재된 경우는 별도 상품명 휴리스틱이 필요할 수 있다.
